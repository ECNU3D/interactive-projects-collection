# 飞机与舰艇展品实施计划

目标：在不回归 M4 的前提下，把 X-57 与 ASR-10 线索升级为完整互动展品；其中舰艇内容必须明确区分历史 ASR-10 避难设施与受其启发的现代救援船教学复合模型。

工作目录：`3d_structure/.worktrees/air-sea-exhibits`

## 任务 1：建立展品注册表与内容契约

1. 先扩展内容测试，断言三件展品全部可用、每件六阶段/十一部件、来源可追溯，并确认 X-57 与 ASR-10 的准确性声明。
2. 运行内容测试，确认新增断言失败。
3. 泛化 `types.ts`，新增 `x57.ts`、`asr10.ts`、`exhibits.ts`，更新 `sources.ts` 与 `catalog.ts`。
4. 运行内容测试与全量单测，确认绿色。
5. 提交一个聚焦的内容契约提交。

## 任务 2：泛化路由、状态、存储和探索页

1. 先扩展 App、ExplorerPage、Gallery、state/storage 测试，覆盖 x57/asr10 路由、动态标题/示意图/部件、独立进度键与非法路由。
2. 运行目标测试，确认失败原因来自硬编码 M4。
3. 让 `ExplorerPage` 接收 `exhibitId`，从注册表读取内容；把 PartNavigator 改为显式接收部件。
4. 扩展 App 路由到三件展品并向页面传递 ID；按展品保存/读取进度。
5. 保留 M4 默认参数和注入式场景 loader，避免破坏既有测试与错误恢复。
6. 运行目标测试与全量单测，提交架构提交。

## 任务 3：实现 X-57 程序化三维展品

1. 先写模型契约测试，要求程序化部件 ID 与内容清单完全一致，并覆盖关键对称布局与十二个高升力电机位置。
2. 运行测试，确认缺少模型而失败。
3. 新建 AircraftModel/AircraftScene；实现机身、机翼、尾翼、起落架、巡航推进、高升力阵列、电池、电力路径、控制器、显示与冷却路径。
4. 所有部件支持拆解偏移、选择高亮、透视外壳和原理动画；为聚焦提供稳定目标。
5. 运行模型测试、ExplorerPage 测试与全量单测，提交 X-57 提交。

## 任务 4：实现 ASR-10 程序化三维展品

1. 先写模型契约测试，要求程序化部件 ID 与内容清单一致，并覆盖双机、双轴、双桨、双舵关系和分舱位置。
2. 运行测试，确认缺少模型而失败。
3. 新建 VesselModel/VesselScene；实现船体、甲板/上层建筑、隔舱、发动机、轴、桨、舵、泵路、驾驶/观察、救援甲板和人员空间。
4. 所有部件支持拆解、透视、选择、聚焦和原理动画；水面只作为舞台表现，不模拟真实海况。
5. 运行模型测试、ExplorerPage 测试与全量单测，提交 ASR-10 提交。

## 任务 5：端到端与视觉验收

1. 读取 Playwright 技能并扩展 E2E：从大厅进入三件展品，切换阶段/模式、选择部件、聚焦、复原、静态降级和返回大厅。
2. 在桌面、平板、手机三种视口运行真实浏览器；采集三件展品的大厅、整机、拆解、透视、原理与知识卡截图。
3. 读取设计审查技能，逐张检查层级、间距、触控目标、文字截断、对比度、几何穿插和空白状态；每个问题修复后重新截图。
4. 检查控制台错误、请求失败和主要交互状态；生产构建通过后再用预览服务器复测关键路径。

## 任务 6：独立审查、文档与集成

1. 更新 README，说明三件完整展品、资料边界和测试命令。
2. 使用独立子代理做规格符合性审查；修复所有关键和重要问题。
3. 规格通过后做代码质量审查；再次修复并复测。
4. 读取完成前验证技能，重新运行全量 Vitest、Playwright 与生产构建，并保存最终截图证据。
5. 检查工作树差异和提交历史；使用开发分支完成技能决定集成方式。由于当前仓库无远端，验证后本地合并到 `main`。
