# 「机械星球」3D 结构科普 Web APP 设计规格

- 日期：2026-07-11
- 状态：首版实现、独立代码审查与真实浏览器验收完成（2026-07-12）
- 首版定位：M4 风格中型坦克完整结构探索样板，飞机与舰艇作为可扩展目录预览

## 1. 产品目标

「机械星球」面向约 8–14 岁儿童及亲子用户，用博物馆式 3D 体验解释大型机械系统如何协同工作。产品不鼓励武器使用，不提供制造、改装、提升杀伤能力或实战操作信息；内容关注历史背景、机械结构、动力传递、观察与工程原理。

首版成功的核心不是藏品数量，而是做出一个足够精细、可验证、可扩展的完整样板：用户能从坦克整体外形进入车体内部，按预设步骤拆解，点击部件阅读短知识卡，查看抽象原理动画，并随时复原模型。

## 2. 首版范围

### 2.1 包含内容

1. 藏品大厅
   - 坦克、飞机、舰艇三个分类入口。
   - M4 风格中型坦克为可进入的完整藏品。
   - 飞机、舰艇各提供一张高质量预览卡，明确标为后续开放。
2. 结构探索室
   - 支持旋转、缩放、聚焦、拆解、透视、部件高亮和一键复原。
   - 六步结构时间轴：整体、外部结构、车体空间、动力与传动、悬挂与行走、关键零件。
   - 每一步可以向前、向后或直接跳转。
3. 知识卡
   - 名称、所属系统、用途、简化原理、观察提示、史料来源。
   - 支持朗读入口和静态文本替代。
4. 学习反馈
   - 每个阶段提供一个无倒计时、无惩罚的观察问题。
   - 提供“看提示”“自动演示”“再试一次”。
   - 进度仅保存在本机，不要求注册。

### 2.2 明确不包含

- 用户账号、云端同步、社交分享、排行榜或广告。
- CMS、管理后台、实时协作或付费系统。
- 精确制造尺寸、材料配方、加工参数、武器改装、射击操作或战术指导。
- 弹药内部、点火链路、火控参数等可转化为操作性武器知识的细节。
- 首版内完整可拆解的飞机和舰艇模型。

## 3. 内容与安全边界

M4 样板采用教育性重建，不宣称是工程级数字孪生。允许展示的高层结构包括：车体、炮塔外壳、炮塔环、动力舱、发动机抽象结构、传动路径、悬挂、履带、乘员空间、观察装置、装甲层次和后坐缓冲的概念性示意。

所有知识卡使用儿童可理解的语言，明确区分“史实”“简化示意”和“观察问题”。涉及争议或无法由可靠来源交叉确认的结构不写成确定事实。模型不会显示精确尺度、可加工剖面或装配公差。

## 4. 核心学习循环

`观察整体 → 拉动拆解 → 选择零件 → 查看原理动画 → 回答观察问题 → 一键复原`

用户既可以自由探索，也可以使用预设导览。首次进入默认开启导览；专业工具不在首屏暴露。每屏只强调一个问题，每次只显示一张知识卡，避免儿童同时处理过多信息。

## 5. 信息架构

### 5.1 藏品大厅

- 顶部：产品标识、简短定位和声音/无障碍入口。
- 主区：三个分类卡片，M4 卡片具有“开始探索”主按钮。
- 辅助区：本次可以学到的三个问题，以及公开史料来源说明。

### 5.2 结构探索室

- 左侧：极简图标导航，包含大厅、探索、藏品索引、帮助。
- 顶部：面包屑、声音、复位和全屏。
- 中央：3D 主舞台，以及拆解、透视、原理三个模式。
- 右侧：当前部件知识卡；窄屏改为可拖出的底部面板。
- 底部：六步时间轴、当前进度和键盘提示。

### 5.3 视觉方向

采用已批准的 A「夜航博物馆」：

- 主色：深海绿与近黑绿，制造安静、沉浸的博物馆环境。
- 结构色：旧金和黄铜色，用于主体机械和时间轴。
- 功能高亮：氧化橙用于当前知识点，青绿色用于辅助系统。
- 文字：象牙白正文，低层信息使用灰绿色。
- 质感：克制网格、局部光晕、低反光金属、轻微颗粒；不使用军械游戏式准星、击杀、等级或战斗化音效。
- 动效：模型入场与拆解具有有节奏的编排；在减少动态模式下改为短淡入或即时切换。

## 6. 3D 模型设计

### 6.1 模型策略

首版坦克使用程序化科普模型，而不是直接引入来源不明的完整外部模型。原因包括：

- 每个部件必须拥有稳定 ID 和独立变换，才能可靠拆解、聚焦和标注。
- 外部扫描模型通常是不可拆分的高面数网格，难以保持统一性能和视觉风格。
- 程序化模型可以明确哪些结构是简化示意，并避免携带不明贴图、徽标或第三方权利。

模型以 M4 的总体机械布局为史料依据，但采用可读性优先的比例与颜色。模型不包含精确尺寸。

### 6.2 部件分组

- `hull-shell`：上车体、下车体和装甲层次。
- `turret-shell`：炮塔外壳、炮塔环与主炮外观。
- `engine-module`：动力舱与抽象发动机结构。
- `transmission-path`：传动方向和驱动轮关系。
- `suspension-left/right`：悬挂单元。
- `track-left/right`：左右履带。
- `crew-space`：仅表示空间关系的半透明体积。
- `observation-system`：观察窗、潜望装置和视线方向。
- `recoil-concept`：仅解释缓冲运动的简化组件。

每个部件记录默认位置、拆解目标位置、所属步骤、功能色、知识卡 ID、可选中范围和无障碍名称。

## 7. 技术架构

### 7.1 技术栈

- Vite + React + TypeScript。
- Three.js + React Three Fiber + Drei。
- React 状态与 reducer 管理确定性探索状态。
- Vitest 与 React Testing Library 负责单元和组件测试。
- Playwright CLI 负责真实浏览器端到端与截图验证。
- 不使用后端；学习进度写入 `localStorage`。

### 7.2 模块边界

1. `content/`
   - 藏品、步骤、部件、知识卡和来源的结构化数据。
   - 不依赖 React 或 Three.js。
2. `experience/`
   - 探索状态、步骤转换、选择、复位和进度。
   - 对外暴露稳定 action，不让界面直接修改 3D 对象。
3. `scene/`
   - 灯光、相机、模型、部件注册、命中测试和拆解动画。
   - 通过部件 ID 与内容层关联。
4. `components/`
   - 大厅、知识卡、时间轴、导航、错误状态和无障碍替代。
5. `pages/`
   - 大厅与探索室的页面组合，不承载底层模型逻辑。

### 7.3 数据流

`选择藏品 → 读取藏品定义 → 创建探索状态 → 渲染部件注册表 → 用户选择步骤/部件 → reducer 生成新状态 → 3D 变换与知识卡同步更新`

状态包含当前藏品、步骤、选中部件、模式、是否自动演示、是否减少动态和加载状态。所有转换可由纯函数测试，避免视觉状态与内容卡不同步。

## 8. 响应式与无障碍

- 桌面使用左侧导航、中部舞台、右侧知识卡和底部时间轴。
- 平板压缩导航和知识卡宽度。
- 手机将知识卡变为底部面板，时间轴变为可横向滚动的大按钮；3D 手势区不会遮挡返回和复位。
- 主要触控目标不小于 44 × 44 CSS 像素。
- 所有拖拽操作都有点按按钮和键盘替代。
- 支持 Tab 聚焦、方向键切换步骤、Enter 选择、Escape 返回、R 复位。
- 自动旋转默认关闭；持续动画可暂停。
- 提供 `prefers-reduced-motion` 响应、清晰焦点环和足够对比度。
- 不只依赖颜色表示系统；同时使用编号、名称和轮廓。
- 屏幕阅读器可以获知当前步骤、选中部件和拆解状态。

## 9. 异常与降级

- WebGL 不可用：显示静态结构示意、六步文字列表和完整知识卡，仍可完成学习流程。
- 3D 模块加载失败：展示明确错误、重试按钮和返回大厅，不显示永久加载器。
- 内容数据缺失：隐藏对应热点并记录开发期警告；页面保留可用状态。
- 本地进度损坏：忽略损坏值并恢复默认进度。
- 运行时不依赖第三方模型服务，避免外部服务不可用导致核心体验失效。

## 10. 性能预算

- 3D 代码在进入探索室时动态加载，藏品大厅不加载 Three.js。
- 桌面目标稳定 60 FPS，中端移动设备目标不低于 30 FPS。
- 使用可复用几何体与材质，限制透明层和实时阴影数量。
- 高像素密度设备限制渲染倍率，移动端降低阴影和后处理质量。
- 页面切换、拆解和复位不得产生明显长任务或控制台错误。

## 13. 测试与验收

### 13.1 单元与组件测试

- 六个步骤之间的前进、后退、跳转和复位。
- 部件选择与知识卡同步。
- 无效本地进度恢复默认状态。
- 减少动态模式关闭持续动画。
- WebGL 降级状态和错误重试。
- 内容数据完整性：每个可点击部件必须有名称、步骤和知识卡。

### 13.2 Playwright 真实浏览器流程

1. 打开藏品大厅，确认三类藏品和 M4 主入口。
2. 进入探索室，等待 3D 就绪并确认无控制台错误。
3. 使用时间轴逐步拆解，检查部件位置和步骤文本同步。
4. 选择发动机、悬挂、观察系统，检查高亮与知识卡。
5. 切换透视和原理模式，再执行复位。
6. 仅用键盘完成步骤切换、部件选择和返回。
7. 使用桌面、平板和手机视口验证布局。
8. 模拟减少动态和 WebGL 不可用状态。

### 13.3 视觉验收

- 截图尺寸至少包括 1440 × 900、1024 × 768、390 × 844。
- 检查首屏层级、模型占比、知识卡可读性、按钮触控面积、文字溢出和遮挡。
- 检查拆解前后截图，确保部件不穿模且标注与目标保持关联。
- 检查深色背景下正文、弱化文字、焦点环和功能高亮的对比度。
- 最终验收以实际浏览器截图和交互结果为依据，不以代码存在代替视觉完成度。

## 14. 完成定义

首版只有在以下条件全部满足时才算完成：

- 藏品大厅和 M4 探索室均可实际使用。
- 六步拆解、部件选择、知识卡、三种模式和复位均正常。
- 关键流程的单元测试和 Playwright 流程通过。
- 桌面与手机截图经过人工视觉检查，没有严重溢出、遮挡、对比度或交互问题。
- 控制台没有未处理错误。
- 来源与许可证信息在项目内可追溯。
- 非 3D 降级路径可读取核心内容。
