# 视觉品质升级方案：3D 建模与 UI 美感改进

日期：2026-07-14
状态：方案（未实施）
范围：三件展品的 3D 呈现、探索室与藏品大厅 UI、设计令牌系统
不改变：内容安全边界、无障碍能力、静态降级路径、状态机与内容层架构

---

## 一、现状诊断

### 1.1 3D 为什么显得"粗糙"

按影响从大到小排序，问题主要不在"程序化建模"这个路线本身，而在渲染管线和材质策略：

**A. 阴影实际上没有开启（bug 级）**
三个 Scene 的 `<Canvas>` 都没有传 `shadows` 属性（`src/scene/VesselScene.tsx:281-294`，Tank/Aircraft 同理），因此模型上散布的 `castShadow` / `receiveShadow` 全部无效。目前唯一起作用的是 `ContactShadows`（分辨率仅 256/512）。零件之间没有互相投影，所有积木看起来像悬浮拼贴，这是"塑料玩具感"的第一来源。

**B. 全局半透明**
`VesselPart.tsx:126-141`（TankPart/AircraftPart 同构）给每个零件的材质固定 `transparent: true, opacity: 0.84`，并对壳体类零件关闭 `depthWrite`。后果：
- 整个模型永远处于 84% 透明度，颜色发灰、形体"果冻化"；
- 透明排序伪影（面片前后闪烁）；
- 拆解模式下"实体机器"的重量感完全丢失。
透明本应是透视/未解锁状态的专属表达，却成了常态。

**C. 金属材质没有反射来源**
材质是 `MeshStandardMaterial`，metalness 0.3–0.42，但场景没有任何环境贴图（未使用 drei `<Environment>`）。PBR 金属在缺少环境反射时会发黑发灰——这是"看起来不像金属、像涂了颜色的泡沫"的直接原因。同时 `ambientLight 0.82 + hemisphereLight 0.5` 的高强度底光把形体明暗压平，五盏灯叠加却没有立体感。

**D. 每个零件一个纯色**
调色板只有 brass/oxide/teal 三色（`VesselPart.tsx:31-50`），一个零件从头到尾一种颜色、零贴图、零粗糙度变化。零件读起来是"色块"而不是"机器"。红/绿/金三色积木感由此而来。

**E. 几何轮廓概括过度**
- 船体 = 一个非均匀缩放的球（`scale=[3.15, 0.84, 1.22]`）+ 两个圆锥（`VesselModel.tsx:109-129`），没有舷弧、折角线、干舷；
- 螺旋桨叶片 = `boxGeometry`；
- 飞机机翼 = 平板，电机舱 = 圆环；
- 细节密度低：窗是盒子、栏杆极细、缺少舱口/把手/警示条/编号等"可信度细节"。
（坦克的 44 节履带实例化、九缸星形发动机排布是好底子，说明程序化路线可以做好。）

**F. 交互反馈弱**
选中零件只有 `scale 1.035 + emissive 0.48`（`VesselPart.tsx:62-93`），没有描边、没有 rim light，孩子很难确认"我点中了什么"。悬停只改鼠标指针。

**G. 输出质量上限低**
桌面 dpr 封顶 1.6、无任何后处理（无 AO、无 bloom、无 SMAA），原理模式的能量脉冲只是一个小透明球，没有发光感。舞台使用 `gridHelper`，是调试工具的观感。

### 1.2 UI 为什么"没有美感"

"夜航博物馆"的概念方向其实是好的（深绿 + 黄铜 + 衬线展签有辨识度），问题在执行层：

**A. 舞台不是主角**
探索页被四面 UI 包死：左侧 78px 导轨 + 顶栏 78px + 右侧 340px 面板 + 底部 132px 时间轴，舞台内部再叠大字标题、模式 tabs、提示气泡堆、相机按钮、零件 chips 条。3D 有效面积约 50%，且被文字压住（`src/styles/explorer.css:1-21`）。

**B. 底部双横条冗余**
零件 chips 行和六步时间轴上下并排，都是横向列表，功能语义不同但视觉完全同构；平板宽度下 chips 被裁切露半截。

**C. 控件无层级**
`border-radius: 0` + 1px 描边方盒是唯一的按钮样式，一屏最多可见约 15 个同权重方盒（看提示/自动演示/我想好了/切换到自由探索/复原模型/模式 tabs/相机 5 键/零件 11 chips……）。没有主次，孩子不知道先看哪、先按哪。

**D. 提示叠层混乱**
右上角"原理模式说明 / 已减少动态 / 播放原理"是三个独立小白盒互相叠压（x57 截图可见重叠错位），像未清理的调试信息。

**E. 大厅对比度过低**
Playwright 截图里 hero 标题是描边空心字，几乎不可见；藏品卡文字在深底上灰度过低。对 8–14 岁读者，正文对比至少要 WCAG AA（4.5:1），当前多处不达标。

**F. 气质偏"成人档案馆"**
全大写英文点缀（GUIDED OBSERVATION / SELECTED MECHANICAL ARCHIVES）、细衬线、无圆角、无插图、无角色、无奖励反馈。信息架构是好的（导览、观察问题、知识卡分层），但视觉语气对目标年龄段太冷。已有的 localStorage 进度数据没有转化为任何可见的成就感。

**G. 设计令牌太薄**
`tokens.css` 只有 14 行：色板 + 两个字体族。没有间距/圆角/阴影/动效时长/层级的系统定义，1678 行的 explorer.css 里到处是魔法数，这是视觉不一致的根源。

## 二、设计方向

保留"夜航博物馆"世界观，把执行基调从**档案馆**调成**儿童科技馆的夜场**：

> 熄灯后的博物馆里，一束追光打在展台上，机器像珍宝一样发亮；
> UI 是玻璃展签和导览员，永远退后半步。

三个关键词，作为所有取舍的判据：

1. **舞台感**：3D 展品占据视觉中心 ≥70%，光是叙事工具（追光、轮廓光、能量辉光）。
2. **珍宝感**：模型不透明、有重量、有反射、有细节密度；透明是"X 光探查"的特权状态而非常态。
3. **导览感**：同一时刻只有一个声音跟孩子说话——提示合并为单一"导览员气泡"，按钮有明确的主次。

## 三、3D 升级方案

按投入产出排序分三层。T1 不动任何几何就能解决诊断 A/B/C/D/F/G 的大部分。

### T1 渲染管线升级（不动几何，预计观感提升 60%）

1. **开启阴影**：`<Canvas shadows>` + 平行光配置 shadow camera（bias、mapSize 1024/2048 按质量档位）。现有 `castShadow` 标注立即生效。
2. **默认不透明**：
   - 常态 `opacity: 1, transparent: false`，恢复 `depthWrite`；
   - 未解锁零件：改用降饱和 + 降 emissive 的"待展出"材质（灰蜡感），而不是半透明；
   - 透视/原理模式的壳体：换专用 X 光材质（Fresnel 边缘发光 + 低透明度 + `side: BackSide` 双 pass，或 drei `MeshTransmissionMaterial` 的低成本配置），让"透视"变成一种有质感的模式特效；
   - `getVesselPartMotion` 等纯函数的 opacity 语义改为材质状态枚举，单元测试同步更新。
3. **环境光照重构**：
   - 打包一张本地小体积室内 HDRI（Poly Haven CC0，≤512px，遵守 README 的许可登记流程），`<Environment files>` 提供反射；或纯程序化：`<Environment>` + drei `<Lightformer>` 摆两三块冷暖光板，零外部资产；
   - `ambientLight` 降到 0.2 以下，hemisphere 降半，保留一盏主追光（暖）+ 一盏轮廓光（冷青）+ 一盏低位补光，明确三点光语法；
   - 金属立刻"活"过来，这是单点收益最大的改动之一。
4. **材质分层**：每个零件从 1 个材质升级为"主体 + 次要 + 点缀"2–3 个材质槽（如发动机：铸铁壳体 + 黄铜缸头 + 红色警示标条）。色板从 3 色扩到 6–8 色，与 UI tokens 一一对应（知识卡上的零件图例色 = 3D 零件色）。可选加程序化 `CanvasTexture` 贴花（编号、舱口线、警示条纹），零外部资产。
5. **后处理链**：引入 `@react-three/postprocessing`：
   - **N8AO**（环境光遮蔽）——零件接缝处出现接触阴影，"悬浮积木感"消失，这是第二个单点收益最大的改动；
   - **Bloom**（selective）——原理模式的能量脉冲、选中零件的高亮真正发光；
   - **SMAA** + dpr 上限提到 2（按质量档位）；
   - **Vignette** 轻量暗角，强化追光叙事。
   - 注意与 `frameloop="demand"` 的兼容（EffectComposer 正常工作，只需保持现有 invalidate 纪律）；低端档位整链关闭，回退到当前效果。
6. **选中/悬停反馈**：postprocessing `Outline`（或 drei `<Outlines>`）金色描边 + 轻微 rim light；悬停时预亮 0.5 档。孩子一眼确认"点中了谁"。
7. **舞台重做**：
   - `gridHelper` 换成实体建模的博物馆圆形展台：金属刻度环 + 哑光台面 + 台缘铭牌；
   - 背景加大半径渐变穹顶（`backside` 球体 + 顶点色渐变）与少量漂浮尘埃粒子（reduced-motion 时静止）；
   - 船的水面升级为轻微法线扰动的着色器水面（保留"抽象水面、非海况模型"的教学定位，reduced-motion 时冻结）；
   - `ContactShadows` 保留作为低端档位方案，高端档位换 `AccumulativeShadows`。

### T2 几何升级（仍程序化，逐展品替换）

原则：不换技术路线（README 的资产许可纪律是项目优点），换建模手法——从"原语拼装"升级为"截面放样 + 车削 + 挤出"。

- **船（asr10）**：
  - 船体用 `Shape` 定义 3–5 个横剖面 + 自写放样（或 `ExtrudeGeometry` 变体）生成带舷弧和折角线的壳体，艏部前倾、艉部方正；
  - 螺旋桨换 `Shape` 挤出的扭转桨叶（3 叶，带桨毂整流罩）；
  - 栏杆 `TubeGeometry` 加粗 + 立柱球节点；上层建筑窗户内凹（挤出负形）；
  - 增加：系缆桩、救生圈（torus + 条纹贴花）、桅杆信号灯（bloom 点）。
- **飞机（x57）**：
  - 机身 `LatheGeometry` 车削（真实的收分曲线 + 座舱鼓包）；
  - 机翼用简化翼型 `Shape` + `ExtrudeGeometry`（带展向锥度与上反角），高展弦比特征立刻成立；
  - 12 个高升力电机舱做成统一的 nacelle 组件（纺锤形 lathe + 桨叶），翼尖巡航电机加大并加整流罩；
  - 尾翼同翼型手法；起落架加轮叉细节。
- **坦克（m4）**：
  - 炮塔用 `LatheGeometry` + 变形做出铸造圆弧感；车体首上/首下折面；
  - 履带已有 44 节实例化，补主动轮齿圈与诱导轮轮辐；负重轮加轮毂细节；
  - 保持教育性概括（README 边界：不做精确尺寸/火控细节），细节密度服务"可信度"而非"军事精确"。
- 通用：所有可见硬边加 bevel；每件展品做 1:1 替换，**保留 part id、focus point、explodeOffset 接口不变**，现有拆解/透视/原理逻辑与测试直接复用。

### T3 资产管线（可选、长期）

若程序化上限仍不满足：Blender 自建低多边形模型 → glTF + meshopt/Draco 压缩 → `useGLTF` 懒加载。自建资产无许可风险；NASA 3D Resources / Smithsonian CC0 可作参考底图。需要评估包体预算（每展品压缩后 ≤ 300KB 为宜）与现有"进入探索室才加载 3D"的懒加载策略衔接。此层不阻塞 T1/T2。

## 四、UI 升级方案

### 4.1 设计令牌系统（一切的地基）

`tokens.css` 从 14 行扩为完整系统：

- **色彩**：保留 ink/ivory/brass/oxide/teal 底盘，补：
  - 功能色（成功/提示/警示，与儿童语境匹配的明亮版本）；
  - 零件强调色 6–8 个（与 3D 材质一一对应，形成"图例即实物"的跨媒介映射）；
  - 全面校对对比度：正文 ≥ 4.5:1，大字 ≥ 3:1（大厅 hero 与卡片是重灾区）。
- **圆角**：0 → 分级体系（chips 全圆、卡片 12–16px、面板 20px）。圆角是对儿童受众最低成本的语气软化。
- **间距/字阶/阴影(elevation)/动效时长与缓动/z-index**：各建 5–7 档 scale，替换 explorer.css/gallery.css 中的魔法数。
- **字体**：展签标题保留宋体/衬线（博物馆气质）；UI 层引入一款 OFL 授权的可爱但清晰的中文字体做子集化打包（候选：霞鹜文楷屏幕阅读版 / MiSans / 思源黑体 Medium，用 cn-font-split 按实际用字子集，控制在 ~100–200KB）；英文装饰词减量、降级为纯装饰纹理。

### 4.2 探索室布局重排（舞台优先）

- **右面板**：改为可折叠的悬浮玻璃卡（现有 backdrop-blur 加圆角、浮起阴影、折叠为窄条），默认展开但可让位给舞台；
- **底部合并**：六步时间轴与零件 chips 合并为一条"旅程条"——上层是 6 个进度节点（点亮式，当前步显示问题文案），零件选择移入右面板的零件清单（带零件色点 + 小图标），消灭双横条；
- **舞台内浮层清理**：
  - 大字问题标题移出 3D 区，与导览气泡合并；
  - "模式说明 / 已减少动态 / 播放原理"三个叠盒合并为**单一导览员气泡组件**（一个出口、一种样式、带指向箭头，依次排队而非叠压）；
  - 相机 5 键收成一个圆形悬浮胶囊组（右下角），图标化；
- **顶栏**瘦身为面包屑 + 复原按钮两端对齐。

### 4.3 组件与层级

- **按钮三级制**：primary（黄铜实心，一屏只允许一个，如"我想好了"）/ secondary（描边）/ ghost（纯文字），全部圆角化、带 hover 位移与按压回弹微动效；
- **零件条目**：圆角胶囊 + 零件色点 + 选中态描边发光，与 3D 描边同色联动；
- **知识卡**：卡头加入零件小图（复用静态降级模式已有的自绘 SVG 资产裁切），"史实依据/简化示意/观察问题"三区块用图标 + 色带区分，来源链接做成展签脚注样式；
- **大厅**：hero 空心字改实心 + 光晕；藏品卡的 SVG 展品图做悬停"聚光灯亮起"动效；卡片信息对比度全面提升；三件藏品配色差异化（陆=oxide、空=teal、海=brass 主导）。

### 4.4 动效编排（一次性投入，气质飞跃）

- **进入探索室的开场编排**：舞台灯亮起（vignette 收缩）→ 模型从展台升起/淡入 → UI 元素 stagger 淡入（150ms 间隔）。一次编排好的入场比散落的微动效更值钱；
- **阶段切换**：时间轴节点点亮 + 相机缓移 + 新零件"就位"动画（现有 damp 逻辑已具备，补充材质过渡）；
- **全部动效走 tokens 的时长/缓动档位，`prefers-reduced-motion` 下按现有纪律整体静止**（现有实现已很规范，保持）。

### 4.5 儿童向激励（利用现有数据，可选阶段）

- localStorage 已存三件展品的学习进度 → 可视化为**观察印章系统**：每完成一个阶段在时间轴上盖一枚印章章纹（与"构"印章同一设计语言），11 零件知识卡做成集卡进度环；
- 大厅藏品卡显示"已观察 8/11 个零件"的进度铜牌；
- 不引入排行/惩罚/时限，与现有"无惩罚观察结论"的产品原则一致。

### 4.6 移动端

- 知识卡改底部上滑 sheet（半开/全开两档）；
- 旅程条压缩为进度点 + 当前问题单行；
- 保留 44px 触控目标与现有键盘/朗读路径。

## 六、风险与约束

1. **透明语义变更**：opacity 从"常态 0.84"改为状态枚举，会改动 `getXxxPartMotion` 纯函数签名与对应单测——工作量可控但要一次性改三个展品保持一致。
2. **后处理性能**：N8AO/Bloom 在低端移动设备有开销 → 沿用 `sceneQuality.ts` 档位机制，受限档整链关闭，保底体验=当前效果+阴影修复。
3. **`frameloop="demand"` 兼容**：所有新增动画（水面、尘埃、bloom 脉冲）必须接入现有 invalidate 纪律，reduced-motion 时冻结——延续现有实现模式即可。
4. **资产许可**：HDRI（Poly Haven CC0）与中文字体（OFL）都必须按 README 的资源登记流程记录 URL/作者/许可证/获取日期；这是项目已有纪律，不能破例。
5. **测试快照更新面大**：P1/P2 会使全部 Playwright 截图基线失效，应按阶段分批重建基线，避免一次性巨型 diff。
6. **内容边界**：几何细节升级严守 README"教育性概括"边界（不做精确尺寸、火控、弹药细节），细节密度服务可信度而非精确复刻。
