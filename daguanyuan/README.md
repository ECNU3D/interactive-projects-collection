# 紅樓夢 · 入府遊

用 Three.js 復原的《紅樓夢》可漫遊三維府第：從寧榮街走進敕造榮國府，穿過五道禮儀之門，經賈母院、榮禧堂，沿寧榮夾道進入大觀園，遍歷瀟湘館、怡紅院、蘅蕪苑、稻香村、省親別墅⋯⋯行至妙處自動觸發語音講解（MiniMax TTS 生成），配以古風背景音樂。

**時序錨定在元妃省親之後**——會芳園牆垣已拆、二府連屬、大觀園建成、姊妹俱已入園（第二十三回之後、第五十四回之前）。

## 運行

需要本地靜態服務器（ES Module 限制，不能直接雙擊 index.html）：

```bash
python3 -m http.server 8430
# 瀏覽器打開 http://localhost:8430
```

右上角常駐小地圖顯示所在院落與朝向（朱色箭頭即視線方向），並畫出推薦線路；走進 33 處看點會自動播放講解並顯示字幕，走近 18 位主要人物會顯示名牌並講其故事。

**界面文字用簡體，畫面內的匾額楹聯用繁體**——後者是清代府第裡真實存在的書法，改成簡體反而失真。

### 關鍵原文

- **第十六回（本項目的地基）**：「先令匠人拆寧府會芳園牆垣樓閣，直接入榮府東大院中。榮府東邊所有下人一帶群房盡已拆去。當日寧榮二宅，雖有一小巷界斷不通，然這小巷亦係私地，並非官道，故可以連屬。會芳園本是從北拐角牆下引來一股活水，今亦無煩再引。」
- **第三回 黛玉進府路線**：西角門 → 一射之地 → 垂花門 → 抄手遊廊 → 穿堂（紫檀架子大理石大插屏）→ 小小三間廳 → 正房大院 → 正面五間上房 → 兩邊穿山遊廊廂房；去賈赦處則「往東過榮府正門，便入一黑油大門中⋯⋯進入三層儀門」。
- **第十七回 遊園次第**：正門五間（桶瓦泥鰍脊、並無朱粉塗飾）→ 翠嶂（障景）→ 曲徑通幽 → 沁芳亭橋 → 瀟湘館 → 稻香村 → 蘅蕪苑 → 蓼汀花漵 → 省親別墅 → 怡紅院。
- **第十七回 水系**：賈珍「原從那閘起流至那洞口，從東北山坳裡引到那村莊裡，又開一道岔口，引至西南上，共總流到這裡」——沁芳溪自東北閘口入園，經凹晶溪館南下，過稻香村分岔，東西兩支繞園一周，匯於沁芳橋。

屋面由「舉折 + 翼角起翹」參數化生成：自檐口 `s=0` 至脊 `s=1`，升高 `y = H·s^1.55`（近檐平緩、近脊陡峻）；廡殿／歇山／攢尖在角部疊加起翹與出翹，硬山不出際、不起翹。

## 音頻再生成

講解詞在 `audio/narrations.json`（33 處地點 + 13 段人物，共 46 段）。重新生成配音／配樂：

```bash
cd audio
python3 gen_audio.py                 # 生成缺少的
python3 gen_audio.py --only xiaoxiang # 只重生成一條
python3 gen_audio.py --bgm            # 只生成配樂
```

密鑰取自 `配音配乐/mini_max_api`。已存在且 >10KB 的 mp3 會跳過；刪掉對應文件即可重生成。地點講解用 `female-chengshu`，人物故事用 `female-tianmei`，兩色分開「導覽」與「說書」。

## 貼圖與性能

- **程序化貼圖**（全部 Canvas 生成，無外部資源）：筒瓦壟、綠琉璃、屋脊、青磚、方磚墁地、卵石花街、漢白玉、太湖石皴、粉牆、黃泥牆、木紋、步步錦／冰裂紋／龜背錦／直櫺櫺心、旋子彩畫、和璽彩畫、蘇式彩畫、茅草、綾羅、宣紙、竹、草地。匾額與楹聯燒進兩張圖集，全園題名共用一個 draw call。
- **枝葉另立一套帶 alpha 的貼圖**（闊葉叢、垂柳條、松針扇、花枝、竹葉、芭蕉葉、草叢野花），以 `alphaTest` 摳背景、雙面渲染，樹冠由交叉竖片組成。比起早先拿球體堆樹冠，面數反而更少（55.4 萬 → 48.5 萬），形態卻細得多——垂柳能看出一縷縷柳條，花木能看出五瓣花與襯葉。
- **色彩管線**：細節貼圖歸一為近白灰度，色調由頂點色承擔，頂點色提亮係數由貼圖實測線性均值反推（`texBoost`），使 `map × vertexColor` 恰好還原調色板色。
- **分塊裁剪**：每座院落為一個裁剪單元（65 個），按玩家距離剔除。
- **規模**：544k 三角面、850k 頂點、475 個碰撞盒、247 個台基平台、62 個裁剪單元；幾何生成合計約 **250ms**（見下）。

## 工具與自檢

```bash
node tools/selfcheck.mjs                    # 自檢：造一遍世界，逐項核對
node tools/route.mjs                        # 重算推薦遊覽線路（改了水系或碰撞後要跑）
node tools/bench.mjs                        # 基準：逐院落量幾何生成耗時與規模
tools/grab.sh out.png "x=-91.2&z=16&yaw=0"  # 無頭取畫（需 Chrome 與本地服務器）
tools/grabs.sh <目錄> "名字|query" ...       # 批量取畫
```

另有 `test.html`（構件試裝台）：把各等級的殿宇、大門、垂花門、影壁、月洞門、遊廊、亭、牌坊、橋、假山一字排開，改動 `js/parts.js` 後可用它快速比對形制。打開 <http://localhost:8430/test.html> 即可。

兩個 Node 工具用最小 DOM/Canvas 樁在無瀏覽器環境下把整個世界造一遍，因此改完數據可以秒級驗證。首次運行需要讓 Node 能解析 `three`：

```bash
mkdir -p node_modules/three && cp lib/three.module.js node_modules/three/
printf '{"name":"three","type":"module","exports":"./three.module.js"}' > node_modules/three/package.json
```

`selfcheck.mjs` 核對的項目：

1. 每個講解點與人物都有講解詞與 mp3，配樂齊備，沒有孤立的講解詞
2. 所有題名都在匾額圖集中（運行期實測，未登記者會回落到第一格）
3. 每個講解點站得住、走得到，觸發半徑內不被碰撞盒塞死
4. 主要人物不站在水面或牆體裡
5. 可入室內的錨點高程與台基吻合（樓上房間豁免）
6. 每座橋確實跨在水上、兩端橋頭上得去；三座園門南北兩側都通得過
7. **全域可達性**：把世界柵格化成 1.5m 的格子，從出生點按與遊戲一致的規則（落水攔住、高差超過 0.62m 攔住、碰撞盒按玩家半徑膨脹）洪水填充一遍，核對每個講解點、每處可入室內、每位主要人物都走得到，推薦線路每一段都走得通
8. **NPC 不穿模**：實例化一整批環境 NPC，核對出生點都站得住，再跑 15 秒虛擬時間，核對沒有一位嵌進碰撞盒或台明立面
9. **水與院不打架**：每座橋（含上下橋頭的外延）不得壓進有院牆的院子、兩端不得落水；院牆不得被溪水穿過；房屋與院門不得泡在水裡
10. 幾何無異常坐標，面數在預算內
11. 分區判定在十個關鍵位置返回正確的院落名

`tools/route.mjs` 在同一張柵格上跑 BFS 逐段串起 35 個站點，再做視線簡化，寫出 `js/data/tour.js`；線路因此**保證可走**，不是照著平面圖描的。

`tools/grab.sh` 直接從 canvas `toDataURL()` 讀回畫面再解碼成 PNG，繞開無頭 Chrome 的合成時序（`--screenshot` 常在異步興造完成前就拍了）。配合 `?still=1` 全程同步興造、`?near=<米>` 只造鏡頭附近的院落（軟件光柵化跑不動全園）。

### 調試參數

| 參數 | 作用 |
|---|---|
| `?still=1` | 同步興造 + 連渲數幀後停住，並把畫面寫入 DOM 供取畫 |
| `?near=120` | 只興造鏡頭附近 120m 的院落 |
| `?x=&z=&yaw=&pitch=` | 指定機位 |
| `?fly=1&h=150` | 鳥瞰 |
| `?map=1` | 直接展開全圖 |
| `?sub=xiaoxiang` | 顯示指定講解的字幕（驗證排版） |
| `?nosoffit=1` | 關掉檐下望板與椽頭（診斷用） |
| `?npc=1` | `near` 模式下仍生成環境 NPC |

## 已知取捨

- 大觀園南北縱深按周長三里半推算得約 640m，實走較遠——故提供 `F` 憑虛御風與地圖神遊兩種代步。
- 建築細部（斗栱攢數、槅扇抹頭數）作了適度簡化以控制面數，形制等級關係保持準確。
- 可入的堂屋一律「開中門」：明間槅扇門向兩側敞開、中間留空。既合迎客開中門的禮制，也讓玩家一眼看出這裡進得去——先前門扇緊閉，雖然碰撞盒留了洞，看上去卻像進不去。
- 小地圖與全圖由同一份布局數據自動生成，非手繪。全圖分「大觀園」「寧榮二府」兩幅並置——原本上下疊成 400×900m 的窄長條，鋪滿屏幕後題名只剩幾個像素。
