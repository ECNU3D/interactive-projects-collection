# 弹珠台（Pinball / Pokémon Pinball 风格） · 完整提示词（GBC 原样复刻）

> 用法：把本文件全文作为一条提示词，发给你的编程 agent（Claude Code / Cursor 等）。
> 文件已包含「GBC 风格总纲」+「原样复刻附加指令」+ 本游戏的具体需求，无需再拼接。

【Game Boy Color 复古风格总纲 —— 以下所有要求为硬性约束】

1. 交付形式：单个 .html 文件，零外部依赖（不引用任何 CDN、字体、图片文件），
   双击即可在浏览器中运行。所有 CSS 和 JavaScript 内联。

2. 画面规格：
   - 使用 <canvas>，逻辑分辨率固定为 160×144（GBC 屏幕分辨率不变，只是有了颜色）。
   - CSS 整数倍放大（3~5 倍自适应窗口），image-rendering: pixelated。
   - 色彩纪律是"像 GBC"的关键：不要用现代渐变和半透明！
     每个精灵（角色/敌人/道具）最多用 3 种颜色 + 透明，
     每个背景图块最多用 4 种颜色，全局同屏颜色控制在 32 色以内。
     颜色选明快高饱和的（GBC 液晶偏淡，游戏都把颜色做得很艳来补偿）。
   - 页面背景做成 GBC 半透明紫色机身（#663399 系），画布嵌在屏幕位置，
     下方画出 GAME BOY COLOR 字标（六个字母 COLOR 用彩虹色，这是情怀细节）。

3. 操作映射（统一全部游戏）：
   - 方向键 = 十字键；Z = B 键；X = A 键；Enter = Start；Shift = Select。
   - 页面底部常驻一行按键说明；同时支持触屏虚拟按键（十字键 + A/B）。

4. 字体与文字：游戏内文字用 8×8 像素字体风格渲染，禁止现代字体直接上画布。

5. 音效：Web Audio API 合成 8-bit 音效（2 个方波 + 1 个噪声通道），
   不加载音频文件。首次按键后再初始化 AudioContext。
   比 GB 版可以奢侈一点：给每个游戏配一段 8~16 小节循环的背景音乐（BGM），
   用音符数组硬编码旋律，方波演奏，音量放低不吵人。

6. 游戏结构：标题画面（游戏 LOGO + 闪烁的 PRESS START）→ 游戏中 →
   Game Over 画面。标题画面要做出 GBC 时代的彩色大 LOGO 感。

7. 手感：requestAnimationFrame 主循环，固定 60fps 逻辑帧，
   区分"按住连发"和"单次触发"，不允许输入丢帧。

【原样复刻附加指令 —— 追加在风格总纲之后，优先级高于总纲中的冲突条款】

0. 项目背景：这是我个人在本地做的怀旧复刻练习，用于测试 AI 编程能力，
   不发布、不分发、不商用。目标是尽量还原原版，而不是做"致敬风格"的改良版。

1. 动手写代码之前，先做资料搜集（如果你有联网搜索/抓取能力）：
   - 到 The Spriters Resource (spriters-resource.com) 搜本游戏的精灵图 (sprite sheet)，
     确认角色的确切像素尺寸、造型、调色板和动画帧；
   - 到 VGMaps (vgmaps.com) 搜本游戏的完整关卡/地图卷轴图，照着转写关卡数据；
   - 搜原版游戏截图，确认标题画面、HUD 布局、字体样式和实机配色；
   - 到 StrategyWiki 或该游戏的专门 Wiki 查证数值（速度、伤害、分值、时间）。
   把查到的关键结论（十六进制配色、精灵尺寸、关卡布局）写进代码注释，方便我核对。

2. 素材落地方式（在"单文件零依赖"前提下二选一）：
   a) 首选：对照参考图，把每个精灵逐像素转写成代码里的二维数组/字符串图，
      用统一的渲染函数绘制——还原度高、可微调、不膨胀文件体积；
   b) 备选：把裁剪好的精灵图转成 base64 data URL 内嵌进 HTML。

3. 还原优先级从高到低：操作手感 > 角色造型 > 关卡布局 > UI与字体 > 音乐。
   拿不准的细节以搜到的原版截图为准，不要自由发挥"现代化改良"。

4. 音乐说明：BGM 贴近本游戏原版曲目的节奏与音色气质来写；若本游戏的原曲
   旋律本身属于公有领域（例如改编自民歌或古典乐的曲目），可直接扒谱使用。
   音效（跳跃、命中、爆炸、菜单声等）务必逐个对照原版还原。

5. 如果无法联网或搜不到资料，就按你训练记忆中的原版样子逐像素重绘，
   宁可朴素也不要走样。

请为我实现 GBC 风格的像素弹珠台（致敬 Pokémon Pinball），单文件 HTML5/JS：

玩法规则：
- 竖版弹珠台，台面为 160×288（两屏高），镜头跟随弹珠上下滚动——
  这是 GBC 弹珠游戏的经典处理。
- 物理（本游戏的灵魂，用简单可控的自研物理，不要引入物理库）：
  重力、弹珠与圆形/线段碰撞反弹、能量衰减；左右挡板用 Z / X 控制，
  挡板击球角度取决于击中挡板的位置和挡板当前摆动速度——手感要"能瞄准"。
- 台面元素：弹射器发射（按住下键蓄力，力度条决定初速）、
  蘑菇弹垫（碰到大力弹开+加分）、旋转门、轨道（进入后沿固定路径加速滑行）、
  中央奖励洞。
- 收集玩法（致敬 Pinball 的抓宠模式）：击中台面 3 个亮灯目标点亮 "CATCH" 模式，
  60 秒内把弹珠打进中央洞即可"捕获"一只初代宝可梦，图鉴 +1（共 6 只，
  造型对照原版《Pokémon Pinball》精灵图，按难度递增出现）。
  集齐 6 只显示图鉴完成画面。
- 弹珠掉落底部损失一颗（共 3 颗）；左右外侧通道上方有可点亮的"救球"灯，
  点亮后掉落一次会被弹回。
- 计分系统：所有碰撞都加分，连续命中有连击倍率；显示 SCORE 和 HI-SCORE。

画面与音效：
- 台面配色艳丽（红蓝黄为主），点亮的灯有闪烁动画，CATCH 模式全台面变色。
- 挡板"啪"、弹垫"boing"、进洞上行琶音、捕获成功的胜利小调。
- 弹珠是 3×3 像素带 1 像素高光，高速时拖残影。
