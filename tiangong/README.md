# 天宫 · Three.js 天宫模拟器

> 你是齐天大圣。天宫在你脚下，你可以飞去任何地方，跟任何一位神仙说话。

一个基于 Three.js 的《西游记》天宫自由漫游作品。程序化生成的明代宫殿群悬于云海之上，40 位天庭神仙各据其位，全部预生成语音，可对话。

**当前状态：可运行。** 全图 16 区域 + 天河渡口已生成，56 个对话包 860 条台词（含 65 条原文直引，CI 校验）+ MiniMax 预生成语音 860 条已打包为 audio sprite，三层 BGM + 场景曲已接入。

```bash
npm install
npm run dev        # 开发（WebGPU，自动回退 WebGL2）
npm run build      # 生产构建（纯静态站点，dist/ 可直接部署）
npm run validate   # 内容 CI：台词↔语音、引文白名单、音色合法性、goto 悬空
# 语音/音乐重生成（增量，需 export MINIMAX_API_KEY=...，密钥不入库）：
npm run gen-voice && npm run pack-audio && npm run gen-bgm
```

**操作**：WASD 驾云 · Shift 加速 · X 降落（落地后走行）· Space 起飞 · 鼠标视角（点击锁定）· C 第一人称 · E 交谈/交互/听书中此处 · **M 全图** · Esc 设置。移动端为虚拟双摇杆，双击右摇杆加速。

**导航**：右上角常驻小地图（当前层俯视 + 朝向 + 右侧五层标尺），M 键展开天宫全图（十九区域平面 + 左侧立面高度尺 + 按层分组的区域名录）。

**书中此处**：十二处关键建筑立有金色信标，按 E 听说书人讲这地方在原著里发生过什么（游戏时间点在偷桃前，故用书外说书口吻）。听过的信标转暗，地图上从金转灰，全图顶部显示 `书中此处 n / 12`。

> 进度**当前不落盘**（`src/core/Store.ts` 的 `PERSIST_PROGRESS = false`）——测试与录像时每次打开都是全新的。读写两条路径都留着，改回 `true` 即恢复 localStorage 存档。

## 三个技术要点

**1. 程序化生成，几乎不用外部模型**
一座中式殿宇由 12 个参数描述（面阔间数、举架系数、斗拱踩数、脊兽数、瓦色……），一行代码生成一座殿，一个种子生成一百座。斗拱、瓦垄、栏杆、脊兽全部走 InstancedMesh，远景走 impostor。这让"三十三座天宫、七十二重宝殿"成为可能。

**2. 语音全量预生成，项目可以是纯静态站点**
约 1180 条语音用 MiniMax T2A 离线批量生成，按角色打包为 audio sprite（42 个文件，不是 1180 个）。运行时零 API 调用、零延迟、零后端、零密钥风险。

**3. 仙气 = 云 + 可见的光 + 有颜色的空气 + 飘动的东西**
四样缺一样，画面就不"仙"。技术上是：体积云（WebGPU compute，带时间重投影）+ 屏幕空间 God Rays + 自定义高度雾（带太阳内散射）+ GPU 粒子。降级路径全部备好。

## 考据立场

本作的一条底线：**凡原著有的，一字不改；凡原著没有的，明确标注。**

研究过程中核实并纠正了五个流传极广的讹误：

| 通行说法 | 原著实况 |
|---|---|
| 二郎神叫**杨戬** | 全书 0 次，出自《封神演义》。原著只有"父姓杨" |
| **哮天犬** | "哮天"全书 0 次，原文作「二郎爷爷的**细犬**」 |
| 二郎神**三只眼** | "三只眼"全书 0 次，写其目只用"**凤目**" |
| 悟空口头禅**俺老孙** | 全书 0 次。原著一律"**老孙**"（618 次） |
| **五指山** | 全书 0 次，原文作「唤名『**五行山**』」 |

还有几条同样重要：**"齐天大圣"不是悟空自封的**（是独角鬼王的建议）；**七十二变斗法中灰鹤是二郎变的**；**镇元子不属天庭**。

游戏内会有一个可折叠的考据栏，标注每一处的原著出处，以及本作自拟内容的说明。这是这个项目从"技术演示"变成"文化产品"的那一层。

## 与文档的偏差（诚实清单）

1. **体积云**：按文档 02 §5.2 的建议路径，使用"分层平面云海 + 覆盖度云洞"作为正式方案；raymarched 体积云未实装（WebGL2/移动端本就走此降级路径）。
2. **屏幕空间 God Rays**：采用文档列的第二种"光锥几何体"方案（TSL 软化光柱），未做径向模糊 pass。
3. **Worker 生成**：区域生成改为加载屏内分帧异步生成（阶段 1 完成即可进入，其余后台续建），未放 Web Worker；实测首屏可交互 < 5s。
4. **Impostor**：宫殿海按等级分组的剪影 InstancedMesh（每等级 1 个 draw call）替代 billboard 图集。
5. **台词规模**：860 条（文档估算 ≈1181），主要角色走满 20–28 条、杂役 8–14 条的结构。
6. **环境音**：按文档 04 §5.1 的"合成"列全部用 Web Audio 程序化合成（钟/鼓/捣药/炉火/风）；标"外采"的项以合成兜底。
7. **字体**：未内置字体文件，运行时使用系统宋体栈；`tools/subset-font.ts` 可在放入思源宋体后产出子集。
8. **蟠桃园株数与尺寸**：原文是「三千六百株」（三段各一千二百），本作实际种 **1200 株**（三段各 400），园子边长 300m。原按原文足数种过，但那个密度下树挨着树、看不出园子的形，近景还要吃六十多万面；减到 1200 株后反而疏朗好看。考据栏里引的仍是原文数字——那是对书的陈述，与游戏内实际株数是两回事。
   株数与尺寸是 `buildPeachOrchard(size, seed, perSection)` 的参数，可随时调回。
   另有三级 LOD 控面数（近 ~700 / 中 ~260 / 远 ~70 tri），按玩家距离重新分桶；三级共用同一套随机序列，花果位置完全一致，切档只换网格精度。
9. **说书人层**：游戏时间点在蟠桃会前夕，而斩妖台、八卦炉、瑶池的高潮剧情在第 5–7 回尚未发生。故采用书外「说书人」层转述，与考据栏同一层次，不伪装成局内旁白。设计见 `docs/superpowers/specs/2026-08-09-书中此处-design.md`。

## 性能

`npm run perf`（需先 `npm run dev`）会跑一遍取证探针：场景规模、三角面、draw call、帧时间分位数、以及**运动平滑度**（同一次运行内对比"原始逻辑位置"与"渲染插值位置"的每帧位移）。

两条不变量，改动渲染或飞行手感后应当复核：

| 指标 | 阈值 | 为什么 |
|---|---|---|
| 渲染插值位置的 `frozenFrames` / `doubleFrames` | **必须为 0** | 逻辑 60Hz 定步长、渲染可变帧率，渲染层不插值就会出现"某帧不动、下一帧走两格"。60Hz 屏上约 14–24% 的帧如此，120Hz 屏上近半数 |
| 稳态可见三角面 | **< 200 万** | 主要预算在蟠桃园。曾经因为桃树无 LOD 达 798 万（占全场 95%），Retina 下掉到 41fps |
