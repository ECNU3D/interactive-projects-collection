## 0. 音频方案总览

| 项 | 决定 |
|---|---|
| 语音方式 | **全量预生成**。无实时 TTS、无后端、无 API 调用发生在运行时 |
| 生成工具 | MiniMax T2A（`/v1/t2a_v2`） |
| BGM | MiniMax 音乐生成（`/v1/music_generation`），纯音乐，三层 stem |
| 环境音与音效 | 少量外部素材 + 程序化合成（Web Audio 直接生成钟、磬、风） |
| 运行时 | 原生 Web Audio API，不用 Howler |
| 部署影响 | **整个项目可以是纯静态站点** |

### 0.1 为什么选预生成

| 维度 | 预生成 | 实时 LLM+TTS |
|---|---|---|
| 延迟 | 0（本地 buffer） | 1.5–4s |
| 成本 | 一次性，约几十元 | 随 DAU 线性增长 |
| 质量控制 | 每一条都能试听、重生成、微调参数 | 不可控 |
| 部署 | 静态 CDN | 需要后端 + 密钥管理 |
| 离线 | 可 | 不可 |
| 自由度 | 有限（对话树） | 高 |

对一个 30–45 分钟的氛围向漫游作品，**预生成是明显更优的选择**。玩家来这里是为了看天宫、听神仙说原著里的话，不是为了跟 AI 聊天。台词精确、有出处、有考据，比"能聊任何话题"更符合本作定位。

**留一个后门**：`VoiceBank` 的接口设计为 `play(id) → AudioBuffer`，将来若要接实时链路，只需换一个 provider 实现，上层不动。

## 1. MiniMax TTS 接入规格

### 1.1 接口

```
POST https://api.minimaxi.com/v1/t2a_v2
备用: https://api-bj.minimaxi.com/v1/t2a_v2
Header: Authorization: Bearer <API_KEY>, Content-Type: application/json
```

**密钥安全**：当前 `配音配乐/mini_max_api` 文件里存有明文 API Key。
- ✅ 已加入 `.gitignore`
- ⬜ **仍需轮换密钥**——明文文件已在磁盘上存在过
- ⬜ 工具链从环境变量 `MINIMAX_API_KEY` 读取，不从文件读

### 1.2 生成参数基线

```jsonc
{
  "model": "speech-2.8-hd",
  "text": "上圣，三界中凡有九窍者，皆可修仙。",
  "stream": false,
  "output_format": "url",          // 批量生成用 url 更省内存；url 有效期 24h，需及时下载
  "voice_setting": {
    "voice_id": "Chinese (Mandarin)_Humorous_Elder",
    "speed": 1.0,                   // [0.5, 2]
    "vol": 1.0,                     // (0, 10]
    "pitch": 0,                     // [-12, 12]
    "emotion": "calm"               // happy/sad/angry/fearful/disgusted/surprised/calm
                                    // fluent/whisper 仅 speech-2.6-* 支持，见 §1.3
  },
  "audio_setting": {
    "sample_rate": 44100,           // 生成端取最高，后期只做一次有损编码
    "format": "flac",               // ★ 无损。不要用 mp3——后面还要转 Opus
    "channel": 1
  },
  "language_boost": "Chinese",
  "subtitle_enable": true,
  "subtitle_type": "sentence"       // 拿句级时间戳做字幕高亮
}
```

### 1.3 模型选择

| 模型 | 特点 | 本作用途 |
|---|---|---|
| **`speech-2.8-hd`** | 最新 HD，**支持语气词标签**（`(laughs)` `(sighs)` `(chuckle)` 等）。**不支持 `fluent` 和 `whisper` 情绪** | **主力**。绝大多数条目 |
| `speech-2.8-turbo` | 更快，同样支持语气词 | 不用（我们是离线批量，不在乎速度） |
| **`speech-2.6-hd`** | **唯一支持 `fluent` 与 `whisper` 情绪**的 HD 模型。不支持语气词标签 | **凡指定 `emotion: fluent` 或 `whisper` 的条目走这个模型** |

> ### ⚠️ 模型与 emotion 的硬约束
>
> API 文档原文：「选项 **`fluent`, `whisper`** 仅对 `speech-2.6-turbo`, `speech-2.6-hd` 模型生效，`speech-2.8-hd`, `speech-2.8-turbo` 模型不支持 `whisper`」。
>
> 这意味着：
> - `emotion: fluent` **在 speech-2.8 上不生效**（不报错，静默退化为默认情绪）
> - `emotion: whisper` 同理
>
> 本作受影响的角色：**张道陵、葛仙翁、虚日鼠、值日功曹、千里眼、顺风耳、引奏仙童、传言玉女**（8 个 `fluent`）+ **嫦娥**（`whisper`）。
>
> **处理**：这 9 个角色的条目在 yaml 中显式覆盖 `model: speech-2.6-hd`（schema 见《02》§8.1）。代价是这些角色不能用语气词标签——他们本来也不需要。
>
> 工具链的 `validate` 脚本必须检查这一条（《02》§9.3）。

### 1.4 古白话的三个坑

这是本作 TTS 的主要技术风险。**必须在正式生成前跑完 §7.1 的试听流程（约 60 条）。**

**坑 1：多音字**

用 `pronunciation_dict.tone` 逐条修正。建立一个全局发音词典：

```jsonc
"pronunciation_dict": {
  "tone": [
    "弼马温/(bi4)(ma3)(wen1)",
    "兜率宫/(dou1)(shuai4)宫",
    "哪吒/(ne2)(zha1)",
    "李靖/(li3)(jing4)",
    "巽/(xun4)",
    "旌阳/(jing1)阳",
    "缃核/(xiang1)(he2)",
    "螭首/(chi1)(shou3)",
    "须弥座/(xu1)(mi2)座",
    "庑殿/(wu3)殿",
    "斗拱/(dou3)(gong3)",
    "鸱吻/(chi1)(wen3)",
    "嬭牙/(nai3)牙",
    "顖/(xin4)",
    "翥/(zhu4)",
    "扆/(yi3)",
    "醄/(tao2)",
    "𨀁踵/(qiang4)(zhong3)"
  ]
}
```

**这张词典是共享资产**，放在 `content/pronunciation.json`，所有生成任务都带上。遇到新的多音字就往里加。

**坑 2：文言节奏**

古白话的断句与现代汉语不同。`speed` 一律**略慢于默认**（0.92–0.98），并在需要停顿的地方插 `<#x#>` 标记：

```
"泼猴何往？<#0.4#>有吾在此，<#0.25#>切莫猖狂。"
```

骈文段落（如朝圣楼的"金钟撞动，三曹神表进丹墀"）停顿要更长，用 `<#0.5#>`。

**坑 3：情绪标注**

`emotion` 默认让模型自动判断，但天宫的台词大多是"表面平静、底下有戏"，模型容易演过。**主要角色一律显式指定 `emotion`**，且优先用 `calm`。

| 角色 | 默认 emotion | 说明 |
|---|---|---|
| 玉帝 | `calm` | 绝不用 angry。他的情绪在原著里全部由叙述者代写，台词本身永远是平的 |
| 王母 | `calm` | |
| 太上老君 | `calm`，缠磨时切 `angry`（但 speed 提到 1.15，做成"不耐烦"而非"发怒"）| 逐条 override，见《02》§8.1 |
| 太白金星 | `happy` | 他永远在陪笑 |
| 四大天师 | 张道陵、葛仙翁 `fluent`（**须走 2.6-hd**）；许旌阳、丘弘济 `calm` | 前两人话密、有表演性，后两人端着。以 §3.2 表为准 |
| 王灵官 | `angry` | 全场唯一真正该用 angry 的地方 |
| 哪吒 | `happy` + pitch +2 | 少年气 |
| 李天王 | `calm` + pitch −3 | 端着 |
| 巨灵神 | `surprised` / `sad` | 他的戏就是尴尬 |
| 孙悟空 | 分句切换，见 §6 | |

### 1.5 语气词标签（`speech-2.8` 专属）

完整清单（19 个）：`(laughs)` `(chuckle)` `(coughs)` `(clear-throat)` `(groans)` `(breath)` `(pant)` `(inhale)` `(exhale)` `(gasps)` `(sniffs)` `(sighs)` `(snorts)` `(burps)` `(lip-smacking)` `(humming)` `(hissing)` `(emm)` `(sneezes)`

用得**极其克制**——每个角色全部台词里不超过 2 处。滥用会让神仙变成播客主播。

推荐用法：

| 角色 | 位置 | 标签 |
|---|---|---|
| 太上老君 | 「(sighs)这泼猴却也缠帐，没有没有，出去出去。」 | `(sighs)` |
| 葛仙翁 | 「(chuckle)苍蝇包网儿──好大面皮。」 | `(chuckle)` |
| 巨灵神 | 「(clear-throat)我乃高上神霄托塔李天王部下先锋巨灵天将！」 | `(clear-throat)` |
| 孙悟空 | 「(laughs)脓包，脓包！」 | `(laughs)` |
| 蟠桃园土地 | 「(breath)仙娥且住！今岁不比往年了——」 | `(breath)` |

### 1.6 错误码处理

| 码 | 含义 | 处理 |
|---|---|---|
| `1002` | 触发限流 | 指数退避重试，最多 5 次 |
| `1039` | TPM 限流 | 降低并发度，等待 30s |
| `1004` | 鉴权失败 | 立即中止，报错 |
| `2049` | 无效 API key（**本仓库的 TTS 文档未列此码，见于音乐 API 文档，待核实是否同样适用于 t2a**） | 立即中止，报错 |
| `1042` | 非法字符超 10% | 检查文本，通常是生僻字或标记符号问题 |
| `2013` | 参数异常 | 检查 voice_id 是否有效 |

> 杂役层的 16 个编号里，编号 28（4 类力士）、29（七衣仙女 7 人）、33（3 人）、31/34/40（各 2 人）实际是**多人共用一个编号**，共 25 个说话人。**条数按人分配，不按编号槽位分配。**

**成本估算**（按 MiniMax 计费字符数）：
平均每条 22 字 → 约 26,000 字符。含试听与重生成的 2–3 倍冗余，总量约 **7–8 万字符**。按公开定价量级估算为**几十元人民币**。
> 具体单价请以 MiniMax 平台当前价目为准，此处不写死。

**音频总时长**：1181 条 × 平均 4s ≈ **79 分钟**。
**打包后体积**：Opus 48kbps 单声道 ≈ **28 MB**，分 **42 个包**（40 NPC + 悟空 + 旁白），按区域下载。
**解码后内存**：Web Audio 一律解到 48 kHz float32 → `79 × 60 × 48000 × 4 B ≈ 910 MB`。**必须 LRU，见 §8。**

### 3.6 混合音色（可选进阶）

MiniMax 支持 `timbre_weights`，最多 4 种音色按权重混合（每种 1–100）：

```jsonc
"voice_setting": { "voice_id": "" },
"timbre_weights": [
  { "voice_id": "Chinese (Mandarin)_Reliable_Executive", "weight": 65 },
  { "voice_id": "Chinese (Mandarin)_Humorous_Elder",     "weight": 35 }
]
```

**建议用于玉帝**：纯"沉稳高管"可能过于现代职场感，混入 35% 的老者音能加上年纪。这是唯一一个值得花时间调混合的角色。

### 3.7 声音效果器（`voice_modify`）

```jsonc
"voice_modify": {
  "pitch": -20,       // [-100,100] 低沉↔明亮
  "intensity": -30,   // [-100,100] 刚劲↔轻柔
  "timbre": -40,      // [-100,100] 浑厚↔清脆
  "sound_effects": "spacious_echo"   // 空旷回音 / 礼堂广播 / 电话失真 / 电音
}
```

| 用途 | 设置 |
|---|---|
| **玉帝**（灵霄殿内） | `sound_effects: "spacious_echo"` —— 让他的声音听起来来自一个巨大的空间。**这一条能极大提升威压感** |
| 广寒宫全部角色 | `timbre: +30`（更清脆）+ 运行时叠冷混响 |
| 兜率宫全部角色 | `intensity: -20`（更轻柔）—— 那里在讲道，没人大声说话 |

> **注意**：`sound_effects` 会写死进音频文件。若同一角色在不同场景出现，宁可运行时用 ConvolverNode 加混响（见 §5.3），不要在生成时写死。**只有玉帝值得写死**，因为他只在灵霄殿出现。

## 4. 背景音乐

### 4.1 设计原则

- **纯音乐**（`is_instrumental: true`）。有歌词会抢台词。
- **不做单曲循环**。做三层 stem 动态混音（见《02》§7.4）。
- **极安静**。天宫的音乐音量应该低到玩家意识不到它在放。它的作用是填补寂静，不是提供情绪。
- **中式配器，但不做民乐大合奏**。用笙、磬、埙、古琴、箫的**长音与泛音**，加少量西方弦乐铺底。参考质感：坂本龙一的空间感 + 佛教梵呗的持续音。

### 4.2 MiniMax 音乐生成接口

```
POST https://api.minimaxi.com/v1/music_generation
```

```jsonc
{
  "model": "music-2.6",              // 付费用户；免费用 music-2.6-free（RPM 低）
  "prompt": "...",                    // 纯音乐时必填，[1,2000] 字符
  "is_instrumental": true,
  "output_format": "url",             // url 有效期 24h，及时下载
  "audio_setting": {
    "sample_rate": 44100,
    "bitrate": 256000,
    "format": "mp3"
  },
  "aigc_watermark": false
}
```

### 4.3 三层 stem 的 prompt

三层必须**同调性、同速度**才能叠。生成时在 prompt 里显式写死 BPM 与调式，并在生成后用 DAW 或 ffmpeg 核对、必要时手工对齐。

**layer_base（垫底，永远在放）**
```
中国传统器乐, 纯音乐, 极简, 环境音乐, 60 BPM, D 羽调式,
持续的笙长音与低频弦乐铺底, 偶尔一声磬, 大量空间混响,
无鼓点, 无旋律走向, 静谧, 庄严, 空旷, 云端, 适合长时间循环不引人注意
```

**layer_melody（开阔区域淡入）**
```
中国传统器乐, 纯音乐, 60 BPM, D 羽调式,
竹笛与埙的悠远旋律, 古琴散音点缀, 弦乐轻柔铺底,
飘渺, 出尘, 悠远, 有呼吸感, 旋律线简单克制不炫技, 大量留白
```

**layer_grand（灵霄殿、朝会事件）**
```
中国传统器乐, 纯音乐, 60 BPM, D 羽调式,
编钟与大鼓的庄严齐奏, 笙管齐鸣, 弦乐群铺满,
恢弘, 神圣, 天庭朝会, 帝王仪仗, 气势磅礴但不喧闹, 有克制的威严
```

### 4.4 场景专属曲目

| 场景 | prompt 要点 | 时长 |
|---|---|---|
| **蟠桃园** | 「中国传统器乐, 纯音乐, 明亮, 温暖, 65 BPM, 竹笛与琵琶轮指, 春日, 花园, 轻快但不欢闹, 有一丝甜」 | 2–3 min 循环 |
| **瑶池** | 「中国传统器乐, 纯音乐, 华丽, 55 BPM, 编磬与筝的琶音, 宴会前的静谧, 期待感, 一丝隐约的不安」 | 2 min |
| **广寒宫** | 「中国传统器乐, 纯音乐, 清冷, 极简, 50 BPM, 独奏箫与冰冷的钟声, 月夜, 孤寂, 遥远, 空灵, 无温暖音色」 | 2 min |

| **南天门（首次进入）** | 「中国传统器乐, 纯音乐, 宏大, 从极静到爆发, 编钟长音渐强, 弦乐群上行, 揭幕感, 60 秒内完成一次情绪抬升」 | 60 s，一次性 |
| **斩妖台** | **无音乐**。只有风声 | — |

### 4.5 音乐的运行时行为

```
玩家所在区域改变 → 目标音乐配置改变 → 3 秒交叉淡入
三层 gain 由"区域 + 事件"共同决定：

           base   melody  grand
蟠桃园      1.0     0.8     0.0    （另叠蟠桃园专属层）
宫殿海      1.0     0.6     0.0
灵霄殿丹墀  1.0     0.3     0.9
朝会事件    1.0     0.0     1.0
斩妖台      0.0     0.0     0.0    ← 音乐完全消失，只剩风
广寒宫      0.0     0.0     0.0    ← 切到专属曲目
```

**斩妖台的"无音乐"是刻意的**。玩家在一路配乐中飞过来，突然安静，会本能地停下。这比任何台词都有效。

## 5. 环境音与空间音频

### 5.1 环境音清单

**来源列**：`合成` = Web Audio 程序化生成（噪声 + 滤波 + 包络，零下载）；`外采` = 需要素材，**必须使用 CC0 / CC-BY 授权**（推荐 freesound.org 的 CC0 区、BBC Sound Effects 的个人使用授权），并在片尾列出出处。

| 音源 | 位置 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| **风** | 全场 | 2D 环境 | **合成** | 粉噪 + 带通滤波，中心频率随高度上移。音量与飞行速度正相关 |
| **云海涌动** | 云层附近 | 2D 环境 | **合成** | 极低频白噪声 + 缓慢 LFO |
| **金钟** | 朝圣楼 | 3D 点源 | **外采** | 玩家可敲。**全场最远的音源，作用是空间导航**——须单独设 `refDistance: 60, maxDistance: 3000, rolloffFactor: 0.5`，否则传不到 800 m 外的南天门 |
| **天鼓** | 朝圣楼 | 3D 点源 | **外采** | 同上 |
| **捣药杵** | 广寒宫 | 3D 点源 | 外采（木杵撞臼） | **有节奏（约 0.8s 一下）**。全场最好的空间音频演示点 |
| **炉火** | 兜率宫八卦炉 | 3D 点源 | 合成 + 外采爆响 | 低频呼呼声 + 偶尔爆响 |
| **风穿巽位** | 八卦炉东南位 | 3D 点源 | 合成 | 只在巽位能听到的风声。**一个用声音藏的彩蛋** |
| **马嘶、蹄声** | 御马监 | 3D 多点源 | 外采 | |
| **酿酒、搬运** | 瑶池长廊 | 3D 多点源 | 外采 | 忙碌的人声与器物声，听不清具体内容 |
| **桃叶沙沙** | 蟠桃园 | 3D 区域源 | 合成 | 滤波噪声 + 随机颗粒 |
| **千龙吐水** | 三台须弥座 | 3D 区域源 | 合成 | 定时奇观触发（本作无天气系统） |
| **甲叶碰撞** | 天丁、天将附近 | 3D 点源 | 外采 | 极轻微，NPC 待机时随机触发 |
| **幢幡猎猎** | 殿前 | 3D 点源 | 合成 | |
| **磬 / 编钟**（BGM 之外的点缀） | 各殿 | 3D 点源 | **外采** | |

### 5.2 空间音频实现

```
AudioBufferSourceNode
  → PannerNode { panningModel: 'HRTF', distanceModel: 'inverse',
                 refDistance: 8, maxDistance: 500, rolloffFactor: 1.2 }
  → ConvolverNode（当前空间的混响 IR）
  → ambientBus
```

用 Three.js 的 `PositionalAudio`（PannerNode 的薄封装，自动跟随 Object3D）。**注意手动调 `refDistance` / `maxDistance` / `rolloffFactor`**——默认 `refDistance = 1` 是为桌面尺度设计的，在天宫这种几百米的尺度下声音衰减得过快，走出十几米就基本听不见了。

上表是通用默认值；**金钟、天鼓**须单独放大（见 §5.1）；**对话语音**须把 `rolloffFactor` 降到 0.3，保证听得清（见 §5.4）。

### 5.3 空间混响

用 ConvolverNode + 若干组 IR（脉冲响应）。IR 可以用程序化生成的合成 IR（噪声 + 指数衰减包络），不需要真实采样。

| 空间 | 混响时长 | 特征 |
|---|---|---|
| 室外（云端） | 0.4 s | 极短，几乎干。天上没有反射面 |
| 宫殿海之间 | 1.2 s | 中等，有远处的回声 |
| 通明殿内 | 2.0 s | 木石大厅 |
| **灵霄宝殿内** | **4.5 s** | 极长。玩家一走进去就听出这个空间大得离谱 |
| 兜率宫丹房 | 1.5 s | 略闷 |
| 广寒宫 | 3.0 s | 冷，高频衰减慢（听起来"脆"） |
| 蟠桃园 | 0.8 s | 有树木吸音 |

**切换**：玩家跨越空间边界时，在 0.5s 内交叉淡入两个 Convolver。

### 5.4 对话时的音频处理

对话开始时：

```
musicBus.gain    → ×0.35   （0.4s 淡）
ambientBus.gain  → ×0.5
voiceBus         → 全量，加轻微 compressor（ratio 3:1）+ 2–4kHz 提亮 2dB
```

对话结束后 0.6s 恢复。

**NPC 语音也走空间化**：即使是对话，语音也应经过 PannerNode 定位在 NPC 的位置上。这样玩家侧头时能感到声音的方位。但 `rolloffFactor` 要设得很低（0.3），保证听得清。

## 6. 玩家角色的配音

### 6.1 配还是不配

**决定：配。**

理由：本作的乐趣有一半在于"听见自己用市井腔跟玉帝说话"。悟空的语言（三叠短语、俗谚、降格修辞）是全书喜剧性的来源，写在字幕里只有一半效果。

**代价**：玩家台词约 300 条，占总量的 1/4，且**必须写成有限的对话树**（不能自由输入）。这个代价是值得的。

### 6.2 悟空的音色

**这是全场最难的一个决定，必须做 A/B 试听。**

候选：

| 候选 | voice_id | 参数 | 评价 |
|---|---|---|---|
| A | `Chinese (Mandarin)_Unrestrained_Young_Man`（不羁青年） | speed 1.15, pitch +2 | 不羁感对，但可能太"现代青年" |
| B | `male-qn-badao`（霸道青年） | speed 1.15, pitch +3 | 有冲劲，可能太硬 |
| C | 混合：`Unrestrained_Young_Man` 60% + `qiaopi_mengmei` 或 `clever_boy` 40% | speed 1.18, pitch +3 | 加入一点"猴气"的尖利与顽皮 |
| D | `Chinese (Mandarin)_Southern_Young_Man`（南方小哥） | speed 1.2, pitch +2 | 市井感最好，但地域色彩可能太强 |

**推荐从 C 开始试**。悟空的声音需要同时具备：年轻、快、尖、顽皮、有点野，且**不能太好听**。太好听就成了偶像剧主角，不是猴子。

**关键参数**：`speed` 必须明显快于所有 NPC（1.15–1.25）。悟空在天宫里是唯一一个说话快的人——所有神仙都慢条斯理，只有他急。这个语速差本身就是角色塑造。

### 6.3 悟空的情绪切换

他是全场唯一需要**逐条指定 emotion** 的角色：

| 语境 | emotion | speed | 例句 |
|---|---|---|---|
| 对上级的假客气 | `calm` | 1.05 | 「老星，你这话说得漂亮。」 |
| 得意 | `happy` | 1.2 | 「老孙便是。」 |
| 讥讽 | `happy` + `(chuckle)` | 1.15 | 「(chuckle)脓包，脓包。」 |
| 真怒 | `angry` | 1.25 | 「养马者，乃后生小辈下贱之役，岂是待我的？」 |
| 意外 | `surprised` | 1.2 | 「有这等事？有这等事？」 |
| 罕见的失落 | `sad` | 0.95 | 用于瑶池席位牌那一段。**全场唯一一次悟空说话变慢** |

**最后一条最重要**。他在瑶池发现自己不在宾客名单上的那一刻，语速降下来，是全作的情绪高点。技术上只是改一个 `speed` 参数，但那是整个项目的支点。

### 6.4 三叠短语的处理

「聒噪，聒噪」「好狠，好狠」「走，走，走」「了帐，了帐」——**必须保留重复，不得合并**。

生成时在重复之间插入短停顿以保证节奏：

```
"聒噪，<#0.15#>聒噪。"
"去<#0.1#>去<#0.1#>去！"
```

字幕同样保留全部重复。

## 7. 工作流

### 7.1 第一步：音色试听（**开工第一件事**）

在写任何对话之前，先跑一遍音色验证。

```
1. 挑 8 个代表性角色（玉帝、老君、金星、哪吒、王灵官、悟空、玉兔、马元帅）
2. 每个角色准备 3 句测试文本：
   - 一句原著原文（验证古白话表现）
   - 一句含多音字的（验证发音词典）
   - 一句带情绪的（验证 emotion）
3. 每个角色试 2–3 个候选音色 → 共约 60 条
4. 生成后横向对比，定稿音色表
5. 特别验证：四大天师连播的辨识度、悟空与所有 NPC 的语速差
```

**不做这一步就批量生成，等于赌博。** 这 60 条的成本可以忽略不计。

试听定稿后，**必须把结果回写《01》§2 的角色表和 §2.5 的玩家音色行**——01 是内容层的唯一事实来源。

### 7.1b 第二步：BGM 三层对齐验证（同样是前置实验）

§4.3 假设三层 stem 能同调同速叠加。这个假设**必须先验证**，不能等到 M3 才发现叠不上。

```
1. 用 §4.3 的三条 prompt 各生成 3 个候选（共 9 条）
2. 导入 DAW 或用 ffmpeg 分析，检查：BPM 是否一致？调性是否一致？起始相位能否对齐？
3. 三层叠加试听，听有无相位抵消、有无节奏错位
4. 若无法对齐 → 走退路：生成三首独立曲子，用"淡出旧曲 + 淡入新曲"替代"叠层"
```

退路会损失一部分"随空间连续变化"的效果，但不影响项目成立。**早发现比晚发现好。**

### 7.2 生成管线

> 完整的 yaml schema 见《02》§8.1；工具链在工程结构中的位置见《02》§2。

```
content/dialogue/*.yaml
   │
   ├─ tools/gen-voice.ts
   │    ├─ 展开条目，合并 角色级 + 行级 voice_setting（《02》§8.1）
   │    ├─ 凡 emotion ∈ {fluent, whisper} → model 强制 speech-2.6-hd
   │    ├─ 注入 content/pronunciation.json 的发音词典
   │    ├─ 计算 sha256(规范化后的完整请求体) → 增量判断
   │    ├─ 并发 4–8 调用 /v1/t2a_v2
   │    │    (output_format: url, format: flac, sample_rate 44100)
   │    ├─ 立即下载（url 仅 24h 有效）→ build/voice-raw/{npc}/{id}.flac
   │    ├─ 保存 subtitle_file（句级时间戳）
   │    └─ 更新 .cache/voice-manifest.json
   │
   ├─ tools/pack-audio.ts
   │    ├─ 响度归一化到 -16 LUFS（loudnorm 双遍，见 §7.3）
   │    ├─ ffmpeg: flac → Opus/WebM 48kbps mono
   │    ├─ 按角色拼接，条间 200ms 静音
   │    ├─ 悟空包按区域拆 4–5 片（见 §8.1）
   │    └─ 输出 public/audio/voice/{npc}.webm + {npc}.json
   │
   └─ tools/validate.ts
        ├─ 每条 yaml 台词都有语音吗？
        ├─ 有孤儿语音吗？
        ├─ quote:true 的台词在 quotes-verified.json 白名单里吗？
        ├─ voice_id 都有效吗？（放行 timbre_weights 分支的空 voice_id）
        ├─ fluent/whisper 条目的 model 覆盖对了吗？
        └─ speed/pitch/vol 都在合法范围内吗？
```

**增量生成是必需的**。1180 条全量重跑既费钱又要等半小时。

**缓存键必须是整个请求体的规范化哈希**，不能只哈希 `text + voice_id`——那样改了 `pronunciation.json`（全局共享、会持续增补）不会触发重生成，会留下一批读错音的旧文件。

### 7.3 响度归一化

**必须做。** MiniMax 不同音色的输出响度差异明显，不归一化的话玩家会一会儿听不见一会儿被吓到。

**必须两遍，且第二遍要回填全部四个测量值 + offset**，只填 `measured_I` 等同于单遍。

```bash
# 第一遍：测量。输出 JSON，取 input_i / input_lra / input_tp / input_thresh / target_offset
ffmpeg -i in.flac -af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json -f null -

# 第二遍：应用。全部回填，并显式设 -ar 48000（loudnorm 内部重采样到 192k，不指定会留在 192k）
ffmpeg -i in.flac -af "loudnorm=I=-16:TP=-1.5:LRA=11:\
measured_I=$IN_I:measured_LRA=$IN_LRA:measured_TP=$IN_TP:measured_thresh=$IN_THRESH:\
offset=$TARGET_OFFSET:linear=true:print_format=summary" \
  -ar 48000 -ac 1 -c:a libopus -b:a 48k out.webm
```

目标：**语音 -16 LUFS，BGM -24 LUFS，环境音 -30 LUFS，音效 -20 LUFS**。

### 7.4 音频总线电平

```
                          ┌── voiceBus    1.00   ← 永远最响
[limiter] → masterGain ──┼── sfxBus      0.70
   ↑                      ├── musicBus    0.35   ← 对话时 ×0.35 再降
   │                      └── ambientBus  0.45   ← 对话时 ×0.5
   └─ DynamicsCompressorNode 作 brickwall limiter
      { threshold: -3, knee: 0, ratio: 20, attack: 0.003, release: 0.1 }
```

**limiter 是必须的**：四路总和 1.00 + 0.70 + 0.35 + 0.45 = 2.5，最坏情况（对话 + 音效 + 音乐 + 环境音同时峰值）会严重削波。masterGain 之前必须挂一个限幅器。

## 8. 运行时架构要点

（完整架构见《02》§7）

| 项 | 决定 |
|---|---|
| 库 | 原生 Web Audio，不用 Howler |
| 语音打包 | 按角色 audio sprite。**42 个文件**（40 NPC + 悟空 + 旁白），非 1181 个 |
| 格式 | Opus in WebM（约为 mp3 的 60% 体积），降级 mp3 |
| 加载 | 按区域预取。玩家进入某区域时拉该区域全部 NPC 的语音包 |
| 自动播放解锁 | loading 页的"入天门"按钮 = 用户手势。点击时 `await ctx.resume()` + 播一帧静音 buffer 彻底解锁 iOS |
| 后台 | `visibilitychange` 时 suspend/resume |
| 内存 | **必须 LRU**，见下 |

### 8.1 内存（最容易算错的一项）

Opus 压缩后总共 28 MB，但 **Web Audio 解码后一律是 48 kHz float32**（无论源文件采样率）：

```
79 分钟 × 60 s × 48000 Hz × 4 B × 1 声道 ≈ 910 MB
```

**不是 200 MB，是接近 1 GB。** 全量常驻在任何平台上都不可行。

**LRU 分档**

| 平台 | 同时驻留的包数 | 约占内存 | 策略 |
|---|---|---|---|
| 桌面 | 10–12 | ~250 MB | 按区域预取，跨层时卸载上一层 |
| 移动端 | **4–5** | ~110 MB | 只保留当前区域 + 悟空当前片 + 旁白包；**对话播完即释放非常驻包** |

**常驻不可卸载**：悟空的"通用片"、旁白/系统包。
**悟空包必须分片**：20 分钟一整包约 230 MB，单独一个就超了移动端预算。按区域拆 4–5 片（天门/宫城/内苑/上层/通用），只驻留当前片 + 通用片。

**降级手段**（若仍然吃紧）：移动端改为**不预解码**，播放时用 `decodeAudioData` 逐条解（有 20–50 ms 延迟，但对话场景可接受，因为对话开始前有相机切换的时间窗）。
