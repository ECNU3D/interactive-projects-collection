# 「书中此处」建筑剧情解说 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在天宫十二处关键建筑放置可按 E 触发的说书人解说，用 MiniMax 预生成语音，并在小地图与全图上高亮尚未探访的剧情点。

**Architecture:** 说书内容做成 `content/dialogue/shuoshu.yaml`，从而复用现有的 gen-voice → pack-audio → validate 管线。原定「不改任何工具」，执行中经用户裁决放宽了一处：Task 2 的审查暴露出 `tools/validate.ts` 的引文校验是宽松双向子串匹配，挡不住「一小段原文 + 一大段自撰」整行打「原文」角标，故新增 Task 10 给它加覆盖率门槛（详见该任务）。除此之外工具链不动。运行时新增 `src/lore/` 三个小模块：`LoreSites`（解析 yaml → 剧情点 + 注册为现有 `Interactable`）、`LoreEngine`（线性播放，复用 `VoiceBank` + `DialogueBox`）、`LoreMarker`（世界里的金色光柱）。进度存 localStorage，地图读它决定金/灰。

**Tech Stack:** TypeScript 5.9 · Three.js 0.185 (WebGPU/TSL) · Vite 7 · js-yaml · Playwright（验证）· MiniMax T2A v2（离线语音）

在 `export const store = new Store<GameState>({` 之前插入持久化读取：

```ts
const PROGRESS_KEY = 'tiangong.progress';

interface PersistedProgress {
  visitedLore?: string[];
}

/**
 * 读存档。隐私模式下 localStorage 会抛异常，吞掉退回空进度即可。
 * 注意：`JSON.parse('null')`（以及 '5'、'"x"'、'true'、'[]' 等原始值/数组）不会抛异常，
 * 会合法返回非对象结果，所以不能只靠 `as PersistedProgress` 类型断言，必须在这里对
 * 解析结果做运行时形状校验，否则非对象会一路传到 `persisted.visitedLore` 处抛出
 * 未捕获的 TypeError，导致模块顶层初始化失败、整个游戏起不来。
 */
function loadProgress(): PersistedProgress {
  try {
    const raw = localStorage.getItem(PROGRESS_KEY);
    const parsed: unknown = raw ? JSON.parse(raw) : null;
    return parsed && typeof parsed === 'object' && !Array.isArray(parsed)
      ? (parsed as PersistedProgress)
      : {};
  } catch {
    return {};
  }
}

const persisted = loadProgress();
```

在 `store` 初值里加：

```ts
  visitedLore: Array.isArray(persisted.visitedLore) ? persisted.visitedLore : [],
```

- [ ] **Step 2: 加读写辅助函数**

在文件末尾（`store` 定义之后）追加：

```ts
function saveProgress(): void {
  try {
    localStorage.setItem(PROGRESS_KEY, JSON.stringify({ visitedLore: store.get('visitedLore') }));
  } catch {
    /* 隐私模式：进度只留在内存里，本次会话仍正常 */
  }
}

/** 标记一处剧情点已听（幂等），并落盘 */
export function markLoreVisited(id: string): void {
  const cur = store.get('visitedLore');
  if (cur.includes(id)) return;
  store.set('visitedLore', [...cur, id]); // 必须换新数组，Store 用 Object.is 判变化
  saveProgress();
}

export function isLoreVisited(id: string): boolean {
  return store.get('visitedLore').includes(id);
}
```

注意 `store.set` 用 `Object.is` 比较，**必须传新数组**，`push` 后再 set 同一个引用不会触发监听。

```ts
/**
 * LoreSites.ts —— 「书中此处」剧情点｜规格 docs/superpowers/specs/2026-08-09-书中此处-design.md
 *
 * content/dialogue/shuoshu.yaml 的 topics 即剧情点：
 * 每个 topic 带 place（区域 id）、at（世界坐标）、source（出处回目）。
 * 该 yaml 同时是 gen-voice / pack-audio / validate 的输入，故是单一事实来源。
 */
import * as THREE from 'three/webgpu';
import shuoshu from '@content/dialogue/shuoshu.yaml';
import type { DialogueFile, DialogueLine } from '../dialogue/types';

export interface LoreSite {
  id: string;
  label: string;
  /** 所属区域 id（content/places.json） */
  place: string;
  position: THREE.Vector3;
  /** 出处回目，播完推给考据栏 */
  source: string;
  lines: DialogueLine[];
}

/** 说书人语音包 id（= yaml 文件名，gen-voice 按此分包） */
export const SHUOSHU_PACK = 'shuoshu';

const file = shuoshu as unknown as DialogueFile;

/** 一次性引子：仅在玩家有史以来第一次触发剧情点时播 */
export const LORE_INTRO: DialogueLine | null = file.greet?.[0] ?? null;

export function loadLoreSites(): LoreSite[] {
  const out: LoreSite[] = [];
  for (const t of file.topics ?? []) {
    if (!t.at || !t.place) continue; // 防御：缺坐标的 topic 不作为剧情点
    out.push({
      id: t.id,
      label: t.label,
      place: t.place,
      position: new THREE.Vector3(t.at[0], t.at[1], t.at[2]),
      source: t.source ?? '',
      lines: t.lines ?? [],
    });
  }
  return out;
}
```

### Task 4: 说书播放器（LoreEngine）

**Files:**
- Create: `src/lore/LoreEngine.ts`

**Interfaces:**
- Consumes: Task 1 的 `markLoreVisited` / `isLoreVisited`；Task 3 的 `LoreSite` / `LORE_INTRO` / `SHUOSHU_PACK`
- Produces:
  - `class LoreEngine { constructor(voice: VoiceBank, box: DialogueBox, audio: AudioCore, hooks: LoreHooks); start(site): Promise<void>; abort(): void; get active(): boolean }`
  - `interface LoreHooks { onSource(site: LoreSite): void; onVisited(site: LoreSite): void }`

- [ ] **Step 1: 写播放器**

创建 `src/lore/LoreEngine.ts`：

```ts
/**
 * LoreEngine.ts —— 「书中此处」线性播放
 *
 * 不复用 DialogueEngine：那个引擎是 greet/topics/goto 对话树，说书是线性序列，
 * 硬套会把两边都弄脏。这里复用更底层的 VoiceBank（含"无语音包→纯字幕"降级）
 * 与 DialogueBox（含字幕字号/对比度设置、原文角标）。
 */
import { store, markLoreVisited } from '../core/Store';
import type { VoiceBank } from '../dialogue/VoiceBank';
import type { DialogueBox } from '../ui/DialogueBox';
import type { AudioCore } from '../audio/AudioCore';
import type { DialogueLine } from '../dialogue/types';
import { SHUOSHU_PACK, LORE_INTRO, type LoreSite } from './LoreSites';

export interface LoreHooks {
  /** 播完：把出处推给考据栏 */
  onSource(site: LoreSite): void;
  /** 播完：marker 转暗、地图刷新 */
  onVisited(site: LoreSite): void;
}

const SPEAKER = '说书人';

export class LoreEngine {
  private stopped = false;
  private running = false;

  constructor(
    private voice: VoiceBank,
    private box: DialogueBox,
    private audio: AudioCore,
    private hooks: LoreHooks,
  ) {}

  get active(): boolean {
    return this.running;
  }

  async start(site: LoreSite): Promise<void> {
    if (this.running) return;
    this.running = true;
    this.stopped = false;
    store.set('inDialogue', true);
    this.audio.duckForDialogue();
    this.box.open();

    // 一次性引子：只在从未听过任何一处时插在正文之前
    const queue: DialogueLine[] = [];
    if (LORE_INTRO && store.get('visitedLore').length === 0) queue.push(LORE_INTRO);
    queue.push(...site.lines);

    try {
      for (const line of queue) {
        if (this.stopped) break;
        await this.playLine(line);
      }
      if (!this.stopped) {
        markLoreVisited(site.id);
        this.hooks.onSource(site);
        this.hooks.onVisited(site);
      }
    } finally {
      this.finish();
    }
  }

  abort(): void {
    this.stopped = true;
  }

  private finish(): void {
    this.running = false;
    this.box.close();
    this.audio.restoreAfterDialogue();
    store.set('inDialogue', false);
  }

  private async playLine(line: DialogueLine): Promise<void> {
    this.box.showLine(line, SPEAKER);
    const dur = await this.voice.play(SHUOSHU_PACK, line.id, line.text);
    if (store.get('settings').autoAdvance) {
      await wait(dur * 1000 + 350, () => this.stopped);
    } else {
      await waitForAdvance(() => this.stopped);
    }
  }
}

/** 可被 abort 提前打断的等待 */
function wait(ms: number, isStopped: () => boolean): Promise<void> {
  return new Promise((resolve) => {
    const t0 = performance.now();
    const tick = (): void => {
      if (isStopped() || performance.now() - t0 >= ms) resolve();
      else requestAnimationFrame(tick);
    };
    requestAnimationFrame(tick);
  });
}

/** 手动推进：等 DialogueBox 置起的 window.__advanceDialogue（与 DialogueEngine 同一约定） */
function waitForAdvance(isStopped: () => boolean): Promise<void> {
  return new Promise((resolve) => {
    const tick = (): void => {
      const w = window as never as { __advanceDialogue?: boolean };
      if (isStopped() || w.__advanceDialogue) {
        w.__advanceDialogue = false;
        resolve();
      } else requestAnimationFrame(tick);
    };
    requestAnimationFrame(tick);
  });
}
```

```ts
/**
 * LoreMarker.ts —— 「书中此处」的世界标记
 *
 * 未听：金色光柱，缓慢脉动；已听：转暗金、不脉动。
 * 加法混合 + depthWrite:false，12 个实例合计 24 个 draw call 量级，
 * 不进阴影与选择性 bloom 的高开销路径。
 */
import * as THREE from 'three/webgpu';
import { Fn, positionLocal, vec4, color, float, uniform, time, sin } from 'three/tsl';
import type { LoreSite } from './LoreSites';

const HEIGHT = 16;
const RADIUS = 1.1;

export function buildLoreMarker(site: LoreSite, visited: boolean): THREE.Group {
  const g = new THREE.Group();
  g.position.copy(site.position);
  g.name = `lore-${site.id}`;

  // 强度 uniform：未听 1.0，已听 0.22
  const strength = uniform(visited ? 0.22 : 1.0);
  (g as never as { __strength: typeof strength }).__strength = strength;

  // 光柱：上细下粗的开口圆柱，顶端淡出
  const geo = new THREE.CylinderGeometry(RADIUS * 0.35, RADIUS, HEIGHT, 12, 1, true);
  geo.translate(0, HEIGHT / 2, 0);
  const mat = new THREE.MeshBasicNodeMaterial({
    transparent: true,
    depthWrite: false,
    side: THREE.DoubleSide,
    blending: THREE.AdditiveBlending,
    fog: false,
  });
  mat.colorNode = Fn(() => {
    const h = positionLocal.y.div(float(HEIGHT)).clamp(0, 1);
    const fade = h.oneMinus().pow(1.6); // 底亮顶淡
    const pulse = sin(time.mul(1.6)).mul(0.18).add(0.82);
    const a = fade.mul(0.5).mul(strength).mul(pulse);
    return vec4(color(0xffe0a0), a);
  })();
  const beam = new THREE.Mesh(geo, mat);
  beam.frustumCulled = false;
  g.add(beam);

  // 地面光环
  const ringGeo = new THREE.RingGeometry(RADIUS * 1.4, RADIUS * 2.0, 32);
  ringGeo.rotateX(-Math.PI / 2);
  ringGeo.translate(0, 0.12, 0);
  const ringMat = new THREE.MeshBasicNodeMaterial({
    transparent: true,
    depthWrite: false,
    side: THREE.DoubleSide,
    blending: THREE.AdditiveBlending,
    fog: false,
  });
  ringMat.colorNode = Fn(() => {
    const pulse = sin(time.mul(1.6).add(1.2)).mul(0.25).add(0.75);
    return vec4(color(0xffe9b8), float(0.55).mul(strength).mul(pulse));
  })();
  const ring = new THREE.Mesh(ringGeo, ringMat);
  ring.frustumCulled = false;
  g.add(ring);

  return g;
}

/** 听完后调用：把光柱压暗 */
export function setMarkerVisited(marker: THREE.Group, visited: boolean): void {
  const s = (marker as never as { __strength?: { value: number } }).__strength;
  if (s) s.value = visited ? 0.22 : 1.0;
}
```

**由来**：Task 2 的审查发现，`tools/validate.ts` 的引文校验是**宽松的双向子串匹配**——台词只要包含任一白名单条目就放行。于是「一小段已核验的原文 + 一大段自撰转述」也能整行过 CI，而 `quote: true` 在 `src/ui/DialogueBox.ts:65-74` 是给**整行**挂「原文」角标的。实测修复前 25 条说书台词覆盖率仅 14%–69%，项目既有 65 条则 98% ≥70%。Task 2 靠一次性人工核验修好了这一批，但人工核验守不住下一批。用户已裁决：给 validate 加常驻门槛，突破计划原本「不改任何工具」的边界。

**Files:**

**Interfaces:**
- Consumes: `content/dialogue/*.yaml` 与 `content/quotes-verified.json`（均已存在）
- Produces: `npm run validate` 新增一条覆盖率校验


Expected: 报出约 23 条 `引文覆盖率不足`，退出码 1。逐条覆盖率数值贴进报告。
若一条都没报出来，说明门槛是空的，必须先修好再往下走。

验完清理：`git worktree remove /tmp/tg-badref`

- [ ] **Step 2: 实现门槛**

在 `tools/validate.ts` 的 `checkLine` 里，`quote` 分支现有的白名单命中判断之后，追加覆盖率计算。要点：

- 复用该文件已有的 squash 逻辑（去 `<#...#>` 停顿标记、去 `(...)` 情绪标记、去 `『』「」` 与空白，再去常见标点），保证与既有匹配口径一致
- 覆盖率 = 命中的白名单条目字数 ÷ 该行 squash 后的总字数；一行命中多条时取**并集长度**而非最长单条（口径更严，也更符合直觉）
- 阈值定为 **0.7**，写成具名常量并加注释说明依据（项目既有 65 条引文 98% ≥70%）
- 低于阈值时报 `err`（错误，非警告），信息里带上 id、实际覆盖率百分比、命中的白名单条目，方便定位
- 阈值常量旁边留一句注释：这条门槛守的是项目底线「凡原著没有的，明确标注」，不要为了让 CI 变绿而调低它
