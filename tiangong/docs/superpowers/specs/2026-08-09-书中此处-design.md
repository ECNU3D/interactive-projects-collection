# 设计 · 「书中此处」建筑剧情解说

日期：2026-08-09
状态：已确认，待实现

## 1. 要解决的问题

天宫十九个区域现在只有建筑和 NPC，没有"这地方在书里发生过什么"。玩家飞到斩妖台，看到的只是一个空台子——不知道日后自己会被押到这里，刀砍斧剁而莫想伤及其身。

要做的是：在十二处关键建筑放置可触发的说书解说，用 MiniMax 预生成语音，并在地图上高亮尚未探访的剧情点。

## 2. 关键约束：叙事口吻

游戏时间点是**蟠桃会前夕**——悟空已受封齐天大圣、已督理蟠桃园，但**尚未偷桃**。而最有戏的建筑剧情（斩妖台行刑、八卦炉四十九日、瑶池席面残乱、灵霄殿外王灵官执殿）全在第 5–7 回，在游戏世界里都还没发生。

**决定：采用书外的「说书人」层。** 说书人明确以"书中此处——日后你……"的口吻讲述，不伪装成局内旁白。

理由：

- 项目已有一个书外层（考据栏，标〔出处〕与「本作设定」），说书人与它同一层次，不破坏世界观自洽
- 可以覆盖完整的第 3–7 回，素材最丰富
- 最符合项目底线「凡原著有的，一字不改；凡原著没有的，明确标注」——说书人转述原文，是最高保真的形式

**被否决的方案**：

- *只讲已发生的（第 3–4 回）*：世界观最干净，但斩妖台、八卦炉、瑶池无内容可讲，恰恰丢掉最好的素材
- *局内谶语式伏笔*：氛围最好，但载不了具体情节，且大部分文本得自拟，与考据底线摩擦最大

## 4. 内容层

### 4.1 单一事实来源：`content/dialogue/shuoshu.yaml`

做成一个"角色对话文件"，从而**完全复用现有内容管线，不改任何工具**：

- `tools/gen-voice.ts` 按 `speaker` 分包，默认 `npc` → 包名取文件名 `shuoshu`
- `tools/pack-audio.ts` 照常产出 `public/audio/voice/shuoshu.webm` + `.json` sprite 索引
- `tools/validate.ts` 照常校验引文白名单、voice_id 合法性、参数区间

结构（`place` / `at` / `source` 三个字段是本功能新增，工具链忽略，运行时读取）：

```yaml
id: shuoshu
name: 说书人
model: speech-2.8-hd
voice_setting:
  voice_id: "Chinese (Mandarin)_Humorous_Elder"
  speed: 1.05
  pitch: -2
  emotion: calm

greet:
  - id: lore_intro_01
    text: "天宫的每一处，书里都写过。要听，便按 E。"

topics:
  - id: zhanyaotai
    label: 斩妖台
    place: zhanyaotai
    at: [390, 143, -270]
    source: 第 6–7 回
    lines:
      - id: lore_zhanyaotai_01
        text: "书中此处——日后你被二郎拿住，绳索捆绑，勾刀穿了琵琶骨，就押到这台上来。"
      - id: lore_zhanyaotai_02
        text: "刀砍斧剁，枪刺剑刳，莫想伤及其身。"
        quote: true
```

`at` 用世界坐标（含层基高），与 `content/places.json` 的 `center` 同一坐标系。

## 5. 代码结构

三个新文件，各管一件事；加三处接线。

### 5.1 `src/lore/LoreSites.ts`

职责：把 `shuoshu.yaml` 的 topics 解析成运行时剧情点，并注册为现有的 `Interactable`。

```ts
export interface LoreSite {
  id: string;          // = topic id
  label: string;       // 建筑名
  place: string;       // 区域 id
  position: THREE.Vector3;
  source: string;      // 出处回目
  lineIds: string[];
  texts: string[];
}
export function loadLoreSites(): LoreSite[]
```

因为复用 `Interactable`（已有 `position` / `radius` / `prompt` / `action`），`main.ts` 里的 E 键分发逻辑**一行都不用改**。

### 5.2 `src/lore/LoreEngine.ts`

职责：线性播放一处剧情。

- `start(site)` → 置 `inDialogue`、音频 duck、逐句 `VoiceBank.play('shuoshu', lineId, text)` + `DialogueBox.showLine`
- `advance()` → E 跳下一句
- 播完 → `Store.markLoreVisited(site.id)`、考据栏推该处出处、恢复音频
- `abort()` → Esc 中断，**不**标记已听

`greet` 里的 `lore_intro_01` 是一次性引子：**仅在玩家触发有史以来第一处剧情点时**，插在该处正文之前播一次；判据是 `store.get('visitedLore').length === 0`。此后不再出现（含跨会话，因为进度已持久化）。

不复用 `DialogueEngine`：那个引擎是为 greet/topics/goto 对话树设计的，说书是线性序列，硬套会把两边都弄脏。复用的是更底层的 `VoiceBank` 与 `DialogueBox`。

无语音包时 `VoiceBank` 已有"纯字幕 + 估算时长"降级路径，本功能直接受益——**没有 API Key 也能完整跑通**。

### 5.3 `src/lore/LoreMarker.ts`

职责：世界里的可见标记。

- 未听：金色光柱 + 缓慢旋转的光环，轻微脉动
- 已听：转为暗金、不脉动
- 实现走 `MeshBasicNodeMaterial` + 加法混合，12 个实例，不进阴影与后处理选择性 bloom 的高开销路径

### 5.4 接线

| 文件 | 改动 |
|---|---|
| `src/core/Store.ts` | 新增 `visitedLore: string[]`；加 localStorage 持久化（键 `tiangong.progress`），读写包 try/catch，不可用时退回内存态 |
| `src/ui/Map.ts` | 小地图与全图绘制剧情点：未听金色脉动、已听灰；全图标题栏加 `书中此处 n / 12` |
| `src/main.ts` | 构造 `LoreEngine`；`loadLoreSites()` 后把 marker 加进场景、把 `Interactable` 推进 `interactables`；E 键与 Esc 分发已有，只需在 `Interactable.action` 里调 `loreEngine.start` |

## 6. 数据流

```
content/dialogue/shuoshu.yaml
   ├─(离线)→ gen-voice → build/voice-raw/shuoshu/*.flac
   │            └→ pack-audio → public/audio/voice/shuoshu.{webm,json}
   └─(构建)→ vite yaml 插件 → JSON → LoreSites
                                       ├→ LoreMarker  → scene
                                       ├→ Interactable → main.ts 的 E 键分发
                                       └→ MapUI        → 小地图/全图标点

按 E → LoreEngine.start → VoiceBank.play('shuoshu', lineId) + DialogueBox
     → 播完 → Store.markLoreVisited → localStorage
                                    ├→ LoreMarker 转暗
                                    └→ MapUI 转灰 + 计数 +1
```

## 7. 错误处理

| 情况 | 行为 |
|---|---|
| 无 `shuoshu` 语音包（未跑 gen-voice） | `VoiceBank` 现有降级：纯字幕 + 按字数估算时长，功能完整可玩 |
| localStorage 不可用（隐私模式） | try/catch 吞掉，进度退回内存态，本次会话内仍正常 |
| 已存进度里有 yaml 中不存在的 id | 忽略该 id，不报错（内容迭代时旧存档不炸） |
| 播放中途 Esc | 中断、恢复音频、**不**标记已听，可重听 |
| 播放中途进入 NPC 对话 | 剧情点与 NPC 的 E 键竞争由现有 `nearestInteractable` vs `npcs.nearest` 就近规则裁决，不新增规则 |

## 8. 验证

| 项 | 手段 |
|---|---|
| 内容合法性 | `npm run validate`——引文白名单、voice_id、参数区间、语音孤儿，已覆盖新 yaml |
| 类型与构建 | `npx tsc --noEmit`、`npm run build` |
| 端到端 | 新增 playwright 冒烟：传送到某剧情点 → E → 逐句播完 → 断言 localStorage 落盘、marker 转暗、地图计数 +1；再断言 Esc 中断不标记 |
| 性能不回退 | `npm run perf`——12 根光柱与地图新绘制不得让稳态三角面破 200 万、不得出现 >33ms 卡顿；插值平滑度 `frozenFrames`/`doubleFrames` 仍须为 0 |

## 9. 明确不做（YAGNI）

- 不做剧情点之间的顺序/解锁依赖，十二处任意顺序
- 不做全局"探索度"成就系统，只有地图上的 `n / 12`
- 不做走近自动播报（会在飞行途中反复打断）
- 不给没有硬原著依据的七个区域硬凑内容

## 10. 前置条件

`tools/gen-voice.ts` 只从环境变量读密钥：`export MINIMAX_API_KEY=...`。在拿到密钥之前，内容层、代码层、地图层可以全部完成并验证——运行时走字幕模式。
